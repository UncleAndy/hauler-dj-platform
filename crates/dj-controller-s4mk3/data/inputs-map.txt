# Where each of the panel's own controls lives.
#
# Format, one control a line, five fields separated by spaces:
#
#   control            report  byte  bit  width
#   deck_a.play_pause  1       4     0    1
#   deck_a.tempo       2       12    0    12
#
# `control` is the name the binding table uses (`deck_a.play_pause`, `mixer.crossfader`, `deck_b.hotcue3`); `report` is
# the HID report number the device sends; `byte` counts from the first byte **after** the report number; `bit` is the bit
# inside that byte and `width` how many bits the field takes (1 for a button, 16 for a knob or a fader, read
# little-endian).
#
# A knob is **twelve bits of value inside a sixteen-bit field**: the device's public description gives
# `Pot.prototype.inBitLength = 16` (the field is two bytes) and `Pot.prototype.max = 2 ** 12 - 1` (the travel is 4095
# counts, whatever the field's width), and the byte offsets agree with the field — the two channels of one knob are two
# bytes apart (the crossfader at 0, the channel faders at 2, 4, 6 and 8, the bands at 44 and 46).
#
# Both halves of that matter, and each was a wrong guess first: read as one byte, a knob jumps (the low byte of a
# sixteen-bit counter runs round eight times while the knob turns once); read as sixteen bits and divided by 65535, a
# knob moves through a quarter of its travel and stops (owner's reports, 24.11). So `width` here is the field's width —
# 16 — and the value is taken as twelve bits.
#
# Provenance: `public-source` — read from Mixxx's public controller description
# (`res/controllers/Traktor Kontrol S4 MK3.hid.xml` and `Traktor-Kontrol-S4-MK3.js`, GPL) as facts about the device, not
# copied as code. Buttons and pads live in report 1; knobs and faders in report 2; every line is confirmed by touching
# the control and seeing the program obey.
#
# Report 3 is not here and will never be: it is the clock and the platters (counters at bytes 8 and 36, wheel positions
# at 12 and 40), and it never carries a button. A line learned there fires by itself and starts decks with nobody near
# the panel.
#
# The pads of the left deck serve decks A and C (the deck button switches), and the right ones B and D; this file binds
# them to A and B, because that is what the engine shows on the two panels.
#
# More controls are learned on the panel: `dj-controller --inputs-learn` asks for one button at a time and writes what it
# saw to `~/.local/share/hauler-dj/inputs-map.txt`. A learned line never overrides a line from this file.
