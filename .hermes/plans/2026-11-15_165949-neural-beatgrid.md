# Срез «нейросетевой уровень и DBN на активациях» (DJP-MEDIA-006)

> **Для Hermes:** это заказ на исполнение. Каждый этап — отдельный коммит со своим зелёным полным
> гейтом (`bash scripts/check.sh`); правка только документов — `bash scripts/check-docs.sh`. Пуш делает
> владелец. Ни одного «TBD»: у каждого шага названы файл, ключ, ожидаемая строка вывода.

## Цель

Закрыть хвост нашего детектора сетки: 19 треков из 123 с F1 ниже 0,5 (уровень уехал или отказ). Замер
15.11 показал, где именно теряется: медиана у нас не хуже нейросети (0,974 против 0,979), а хвост — хуже
(65,9 % треков ≥ 0,9 против 87,2 %). Причина — выбор метрического уровня; модель Beat This! решает его
верно в 92 % против наших 79,4 %.

## Основание (замер 15.11.2026, 125 треков raveform)

| Схема | F1 ср | F1 ≥ 0,9 | CMLt мед |
| --- | --- | --- | --- |
| наши доли | 0,819 | 65,9 % | 0,848 |
| уровень модели + постоянная сетка | 0,913 | 82,4 % | 1,000 |
| доли модели как есть | 0,956 | 87,2 % | 0,589 |
| где уровень модели верен (115/125) | 0,954 | 89 % | 1,000 |

Подробности и разбор отвергнутых схем — `docs/qa/evidence/A15/raveform.md`, «Проверка внешней модели» и
«Гибрид: что проверили».

## Этапы

### Э1. Внешний уровень темпа в детекторе (гибрид A)

- `crates/dj-analysis/src/tempo.rs`: тип `LevelPrior { bpm: f64, tolerance: f32 }` и вход
  `detect_with_prior(mono, rate, Option<&LevelPrior>)`; `detect` остаётся обёрткой с `None`.
- Правило: после штатного конвейера привести сетку к уровню приора — отношение берётся из лестницы
  (1/2, 2/3, 3/4, 4/5, 1, 5/4, 4/3, 3/2, 2) и применяется ко всем сегментам; затем фаза пересчитывается
  заново (`snap_to_onsets`, `on_the_beat_side`) — прежняя фаза относится к прежней сетке.
- `gridbench --level-prior <tsv>` (id → BPM) для замера на корпусе.
- Приёмка: без приора результат байт-в-байт равен `detect` (свидетель — существующие 26 тестов и
  golden); с приором от модели уровень ≥ 92 %, сохранено ≥ 80 из 81 нашего попадания; отдельный тест на
  фикстуре: приор вдвое ниже штатного даёт сетку вдвое ниже.
- Замер 125 треков: ожидание F1 ≥ 0,91 при CMLt ≥ 0,99.

### Э2. ADR-0012 и манифест модели

- `docs/adr/0012-external-beat-model.md`: модель не в репозитории и не в дистрибутиве, ставится по
  запросу, лицензия и атрибуция в интерфейсе, приложение полностью работает без неё.
- `model.toml` в репозитории — только описание: id, версия, официальный URL, SHA-256, размер, SPDX,
  атрибуция, ссылка на текст лицензии. Записей **две** — `small` и `full` (ADR-0012, «Две величины
  одной модели»), у каждой свой размер, хэш и измеренное качество.
- Приёмка: `check-docs.sh` зелёный; в репозитории нет ни одного файла весов (проверка размеров в гейте —
  Э4).

### Э3. Экспорт ONNX и сверка с PyTorch

- Вне репозитория: `torch.onnx.export` для `final0` (вход — мел-спектрограмма [1, T, 128], выход — два
  логита [1, T]). Сверка: max |Δ| по 20 трекам < 1e-4.
- Манифест получает SHA-256 и размер ONNX-артефакта; сам артефакт хостится отдельно (не в git).

### Э4. Triton и загрузчик

- `models/beat_this/1/model.onnx` + `config.pbtxt` (backend onnxruntime, динамическая ось по времени).
- Клиент — `tritonserver-rs`; загрузчик: HTTPS, проверка SHA-256, каталог
  `$XDG_DATA_HOME/hauler-dj/models/<id>/<version>/`, экран лицензии до скачивания, «Удалить» возвращает
  классический детектор.
- Выбор варианта — по доступности: есть `full` — он, есть только `small` — он, нет ни одного —
  классический детектор. Правило живёт в одном месте (резолвер модели), а не в вызывающем коде.
- Приёмка: без сети и без модели всё работает на классическом детекторе (тест); при подменённом хэше
  загрузка отвергается (тест); `--model-check` в оболочке показывает, что уровень пришёл от модели.

### Э5. DBN по активациям модели

- Состояния (темп × фаза), переход `exp(-100·|ln(ratio)|)`, наблюдение λ = 16, `beats_per_bar = [4]`,
  Viterbi по кадрам 50 Гц; наш слой — сетка из декодированной последовательности (период и фаза по
  сегментам).
- Приёмка на 125 треках: F1 ≥ 0,95, CMLt ≥ 0,80, уровень ≥ 95 %; на отложенной половине корпуса —
  те же пороги.

### Э6. Продуктовая обвязка

- «Переанализировать всё» с очередью, сохранение ручных правок (замок и правка сетки не затираются),
  показ времени анализа, откат на классический детектор.

## Э4б: сборка Triton core из исходников (состояние на 15.11.2026)

Выбран путь in-process (C-API), по скиллу `triton-server-from-source`.

Сделано:

- исходники: `tmp/triton/core` и `tmp/triton/onnxruntime_backend` на теге `r24.08`, ONNX Runtime 1.18.1
  распакован в `tmp/triton/ort` (всё в gitignored `tmp/`);
- скрипты сборки — `tmp/triton/build_all.sh` (configure + build + install, `JOBS=6`);
- починена синтаксическая ошибка в скилле: `-esac` → `esac` в `scripts/triton_build_env.sh`;
- песочница без `/bin`: make и configure-шаги ищут `/bin/sh` — ссылка создаётся в начале каждого
  прогона (`mkdir -p /bin && ln -sfn /run/current-system/sw/bin/bash /bin/sh`), потому что корень —
  свой tmpfs на каждый вызов;
- в dev shell нет `python3`, а его зовут grpc-repo и python-цели — каталог python добавлен в `PATH`;
- системные protobuf/abseil/re2 убраны из `CMAKE_PREFIX_PATH`, вместо них публикуются конфигурации
  третьей стороны, которую ядро собирает само (`third-party/<pkg>/lib64/cmake/<pkg>`);
- внешний configure проходит, сборка доходит до компиляции ядра.

Блокер: **третья сторона не компилируется GCC 15** — `protobuf/include/google/protobuf/map_field_inl.h`
(`could not convert std::string_view to std::string`, `no declaration matches …`). Это тот же класс, что
CMake 4 и `<cstdint>`, но про компилятор, а не про CMake.

Варианты: собрать ядро с GCC 13 из nixpkgs; либо добавить `-std=c++17`/`-Wno-error` для третьей стороны;
либо вернуться к вопросу, нужен ли Triton вообще для одной ONNX-модели (прямой `ort` не требует сборки).

## Э4б: решение по движку (15.11.2026)

Triton отклонён, движок — `ort` (ADR-0013). Основание — замер выше и блокер сборки: третья сторона
Triton r24.08 не собирается GCC 15, а для одной модели и одного вызова на трек выигрыш Triton не
используется. Сборочное дерево `tmp/triton` (3,1 ГБ) остаётся в gitignored `tmp/` как материал, если
к Triton вернутся.
