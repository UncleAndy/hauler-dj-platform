# Джоги S4 MK3: подсветка, скрэтч, фаза

> **Для Hermes:** три задачи владельца (25.11). Каждая — отдельный коммит со своим зелёным прогоном.
> Часть фактов — `public-source` из Mixxx (номер репорта, смещение), их надо подтвердить на панели
> (`observed`) до объявления задачи сделанной. Без панели задачи 2–3 проверяются `--replay`, задача 1 — нет.

## Связанный план

Управление жестами с клавиатуры (двойное нажатие против автоповтора, бросок к краю и середине шкалы, скрэтч через
`DjCommand::Hand`) и движок профилей, в который устройство добавляется данными, — отдельный план:
`.hermes/plans/2026-11-26_221111-controller-profiles-and-keyboard.md`. Здесь остаются только джоги самой панели;
`Hand`-жесты там переиспользуют ту же команду руки, поэтому правка «рука помнит предыдущую скорость» касается обоих.

## Цель

1. **Подсветка играющего джога** — кольцо вокруг платтера светится у играющей деки (и гаснет у стоящей).
2. **Скрэтч:** касание верхней поверхности — остановка; движение под касанием — скрэтч.
3. **Фаза:** вращение джога **без** касания верхней поверхности — подстройка фазы (bend) играющей деки.

## Собранные факты

- **Позиция джога** — report 3: левый uint32 LE с байта 12, правый с 40; таймер uint32 LE в байтах 8 и 36.
  Уже декодируется драйвером в `wheel_left` / `wheel_right` (`crates/dj-controller-s4mk3/src/lib.rs`,
  `dj_controller_core::WheelCounter`): `speed = Δпозиция / Δтаймер`, переполнение 32 бита учтено.
  **`WheelCounter::speed` — тики на единицу таймера, не кадры/с.**
- **Касание джога** — отдельная кнопка report 1: левый (дека A) байт **16 бит 4**, правый (дека B) байт
  **16 бит 5** (`wheelTouch`, `Traktor-Kontrol-S4-MK3.js:3645,3698`, `public-source`). В `inputs-map.txt`
  этих строк нет — их надо добавить.
- **Логика Mixxx** (`...js:3115`): `wheelTouch.touched || scratch2 !== 0 ? scratch2 = speed : jog = speed`,
  то есть касание → скрэтч, без касания → bend. Ровно задачи 2 и 3.
- **Подсветка кольца** — выход **50**, 40 байт: `[0]=дека` (0-based), `[1]=режим` (`wheelLEDmodes`:
  `off=0, dimFlash=1, spot=2, ringFlash=3, dimSpot=4, individuallyAddressable=5`), `[2..3]=позиция метки`
  (LE, при `spot`), `[4]=цвет+brightness`, `[8..40]=сегменты` (при `individuallyAddressable`). Инициализация
  кольца — отдельный выход **48** (26 байт: б1=1, б2=3, б0=1, дважды). **`protocol-notes.md` знает только 48,
  не 50** — выход 50 в наших заметках отсутствует (`public-source`, из JS `sendOutputReport(50, …)`).
- **Команды движка уже есть:** `DjCommand::Hand { deck, speed: кадры/с signed, held }` (скрэтч; скорость
  физическая, движок переводит в свои единицы) и `DjCommand::Nudge { deck, amount: −1…1 }` (bend). Обе
  коалесцируются (`CoalesceKey::Nudge` и т.д.). Окно уже гоняет `Hand` с волны — путь проверен.

## Что мешает сделать «вслепую» (нужна панель)

- **Q1. Единицы таймера отчёта 3** (байты 8/36): мс, мкс, свои тики? От этого зависит перевод `speed`
  в кадры/с для `Hand` и в −1…1 для `Nudge`. Измеряется: `dj-controller --capture` при N оборотов джога,
  затем Δтаймер/оборот. **Рекомендация:** снять запись, посчитать; до этого scale — настройка.
- **Q2. Выход 50** не в `protocol-notes.md`. Структура снята из JS (`public-source`), но на панели не
  проверялась. **Рекомендация:** проба как у карты подсветки — новый инструмент (например
  `--wheel-light <deck> --mode <n> [--position p] [--colour c] --send`), владелец смотрит, что загорелось;
  только потом вшивать в цикл подсветки.
- **Q3. Масштабы** (`кадры/с` на оборот/сек для скрэтча; −1…1 на оборот/сек для фазы) — это «на слух/глаз»
  владельца, как законы ручек. **Рекомендация:** вынести в `[controller]` настройками (как `pitch_range`),
  дефолт разумный, владелец крутит.

## Этапы

### Э1. Вход касания + маршрут колесо → команда (задачи 2 и 3, без панели проверяемо)

- `inputs-map.txt`: `deck_a.wheel_touch 1 16 4 1`, `deck_b.wheel_touch 1 16 5 1` (плюс строки C/D, если
  джогов у них нет — нет; стороны ведут A/C и B/D, см. Q4).
- `apps/dj-controller/src/main.rs`: в `inputs_loop` держать `touched[side]` (из `deck_*.wheel_touch`), и на
  `wheel_left`/`wheel_right`:
  - касание стоит → `DjCommand::Hand { deck, speed: <scale>, held: true }`;
  - касания нет → `DjCommand::Nudge { deck, amount: <scale> }`.
  На press касания → `Hand { held: true, speed: 0 }` (стоп), на release → `Hand { held: false, speed: 0 }`.
- Масштабы — `[controller]` настройки (`scratch_frames_per_rev`, `nudge_per_rev`), дефолт подберём.
- **Свидетель без панели:** `--replay` строк `deck_a.wheel_touch=1`, `wheel_left=<v>` → `Hand`, без касания →
  `Nudge`; `dj-controller` печатает команду. Плюс тест `WheelCounter` уже есть.

### Э2. Подсветка кольца (задача 1) — после пробы выхода 50

- Новый слой записи `dj-hid::write` для отчёта 50 + инициализация 48 (как у 128).
- В цикле подсветки (там, где собирается `Show`): у играющей деки — `spot` с позицией плейхеда
  (из `source_frame / total`), у стоящей — `off`. Цвет — `controller.lights`-имя (или новый ключ).
- **Свидетель без панели:** сухая половина печатает `would light wheel A, mode spot, position …, colour …`,
  `controller-check` требует, чтобы у играющей деки появился кадр 50.

## Карта проверок

| Что | Чем держится |
| --- | --- |
| Касание → стоп, движение под касанием → `Hand` | `--replay` + вывод команды |
| Движение без касания → `Nudge` | `--replay` + вывод команды |
| Кольцо горит у играющей, гаснет у стоящей | `controller-check` (сухой вывод кадра 50) |
| Панель: касание/кольцо действительно так | `--inputs-watch`, `--wheel-light --send` (владелец) |

## Открытые вопросы (с рекомендацией)

- **Q4. Джог ведёт деку стороны или всегда A/B?** На панели левый джог — физически дека A, правый — B, но
  стороны `panel.left/right` могут указывать на C/D. Транспорт уже переадресуется в деку стороны
  (`follow_side`). **Рекомендация:** так же и джог — ведёт деку своей стороны (иначе «джог A шрэтчит C»).
- **Q5. Скрэтч и фаза одновременно на двух деках?** Обе команды per-deck, конфликта нет.
- **Q6. Моторы** не трогаем: `Hand`/`Nudge` звуковые, не моторные. Моторный джог — после ADR-0007, вне задач.
