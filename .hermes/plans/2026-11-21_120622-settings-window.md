# Окно настроек приложения

> **Для Hermes:** каждый этап — отдельный коммит со своим зелёным прогоном (`bash scripts/check.sh` перед
> коммитом). План — заказ: по нему исполняют, раскладку и содержание заново не обсуждают. Решения владельца
> 21.11 внесены в §2 и §4 как принятые, а не как вопросы.

**Цель:** одно окно, в котором DJ меняет то, что сейчас лежит в трёх файлах и в флагах командной строки:
звук, анализ, библиотеку, микшер, эффекты, интерфейс, диагностику, а также видит версию и лицензии.

**Архитектура:** окно — не «диалог с полями», а новая модель `SettingsModel` (C++), которая знает, **кто**
владеет каждым значением, и пишет через владельца: `LayoutSettings` (`layout.json`), `SessionState`
(`session.json`), `UiSettings` (оболочка) и новый узкий писатель `EngineSettings` (`config.toml`, только
запись — движок читает его при старте). Окно задаёт **умолчания**; живые органы остаются на панелях.

**Стек:** Qt 6.11 QML + C++, `dj-config` (типы `Config`, `AudioSettings`, `HeadphoneSettings`, …), проверки в
`apps/dj-ui/src/checks/`.

**Исходники (проверено в коде 21.11):**

| Факт | Где |
|---|---|
| `config.toml`: `audio{device, sample_rate, block_frames, prefetch_seconds, headphones{mode, device, pair, gain, mix}}`, `loop_playback.buffer_max_seconds`, `pcm_cache{…}`, `diagnostics{…}`, `realtime{priority, require}`, `display{state_hz, frame_hz}`, `analysis.auto_gain_share`, `library{history_min_seconds, played_recently_hours}` | `crates/dj-config/src/lib.rs` |
| `layout.json`: `preset`, доли областей, `deckRows`, `channelOrder`, `browserFont`, `browserRailWidth`, `collectionRoots`, `waveformSpan/Beats`, `snapGrid`, `quantizeGrid`, `scrubAudible`, колонки | `apps/dj-ui/src/LayoutSettings.h` |
| `session.json`: папка, курсоры, форма окна, `crossfader_curve`, `deck_fx` | `apps/dj-ui/src/SessionState.h` |
| `UiSettings`: 16 цветов темы, цвета/стиль волны, `frameHz`, `waveformZoom/BarWidth/BarGap`, `pitchRangePercent`, `gainCurve/faderCurve` с серединами | `apps/dj-ui/src/UiSettings.h` |
| Синглтоны QML: `LayoutState`, `Session`, `UiSettings`, `Bridge` | `apps/dj-ui/src/main.cpp:908` и рядом |
| Только флаги, в окне их нет: `--waveform-contrast`, `--waveform-zoom`, `--fps`, `--waveform-style/bar-width/bar-gap`, `--gain-curve`, `--fader-curve`, `--scrub-mode`, `--channel-order`, `--layout` | `apps/dj-ui/src/main.cpp` |
| Перечисления устройств нет: только `resolve_device(Option<&str>) -> Result<DeviceShape, IoError>` | `crates/dj-audio-io/src/lib.rs:213` |

## 1. Решения владельца (21.11)

1. **Хранение — три файла остаются.** Окно маршрутизирует запись через владельцев; сведение к одному
   `settings.toml` — отдельный заход, не этот.
2. **Звуковые настройки применяются после перезапуска** (вариант «а»): окно пишет `config.toml` и честно
   помечает раздел «применится после перезапуска движка». Самоперезапуск движка — не сейчас.
3. **Темы — наборами**, а не редактором отдельных цветов: три-четыре именованных набора, применяются целиком.

## 2. Принципы окна

1. **Окно — умолчания, панель — живые органы.** Кривая кроссфейдера, вид эффекта, фейдеры остаются на
   микшере; окно задаёт значение, которое подхватит следующий запуск. Дубль живого контрола запрещён: два
   источника одного значения расходятся.
2. **Ни одного контрола, который код не читает.** Уже известный долг такого рода: середина кривой ручки
   (`--gain-curve-middle`) едет, но не влияет. Каждая строка окна обязана иметь владельца и проверку.
3. **Пометка «после перезапуска» — часть интерфейса,** а не примечание в документации: значения, которые читает
   только движок, стоят под баннером, и баннер исчезает, когда раздел пуст.
4. **Окно не пишет файлы само.** Один писатель на файл (см. §4), иначе `layout.json` получает двух авторов и
   один затирает другого.

## 3. Содержание: восемь разделов

Каждая строка — контрол, его владелец и статус: «живёт» (применяется сразу), «рестарт» (нужен перезапуск
движка), «новое» (нужен код до контрола).

### 3.1 Звук — `config.toml` (рестарт)

| Контрол | Поле | Статус |
|---|---|---|
| Устройство вывода | `audio.device` | строка + кнопка «Проверить» (`resolve_device`), список — после перечисления устройств |
| Частота | `audio.sample_rate` | 44100 / 48000 / 96000 |
| Блок | `audio.block_frames` | 64…1024, подпись с периодом в мс |
| Префетч | `audio.prefetch_seconds` | 1…30 |
| Режим наушников | `audio.headphones.mode` | `auto` / `same_device` / `device` |
| Пара каналов | `audio.headphones.pair` | (0,1) … (2,3) |
| Устройство наушников | `audio.headphones.device` | строка, только при `device` |
| Громкость и микс наушников по умолчанию | `audio.headphones.gain/mix` | 0…1 |

### 3.2 Анализ — `config.toml` (рестарт для модели) + окно модели

| Контрол | Поле | Статус |
|---|---|---|
| Путь замера удара | модель / встроенный детектор | «новое»: нужен флаг в конфиге вместо `DJ_BEATMODEL` |
| Доля автогейна | `analysis.auto_gain_share` | 0…1, по умолчанию 0,7 |
| Замер тональности при загрузке | — | «новое»: сейчас всегда включён |
| Окно модели | лицензия (MIT), размер, sha256, кнопка «Скачать» | «новое»: файла модели нет в дистрибутиве Windows |

### 3.3 Библиотека — `layout.json` (живёт) + `config.toml` (рестарт)

Версия, протокол (`bridge-v1`/`state-v1`), лицензии (`LICENSES/`, `THIRD_PARTY.md`), лицензия модели удара,

## 4. Кто владеет записью

| Значение | Владелец сегодня | Как пишет окно |
|---|---|---|
| Раскладка, корни коллекции, режимы деки | `LayoutSettings` → `layout.json` | через `LayoutSettings` (существующие сеттеры) |
| Кривая кроссфейдера, вид эффекта | `SessionState` → `session.json` | через `SessionState.remember*` |
| Законы ручек/фейдеров, частота кадров, цвета | `UiSettings` | через `UiSettings` (эти свойства уже живут в оболочке) |
| Звук, анализ, кэш, диагностика, библиотечные пороги | `dj-config` → `config.toml` | через `EngineSettings` — **новый** узкий писатель TOML с проверкой типов |

`EngineSettings` — единственное новое хранилище: он читает существующий `config.toml` (через
`dj_config::Config`), меняет одно поле и пишет файл обратно целиком, не теряя незнакомых ключей. Тест —
круговой: файл с чужими ключами и комментариями → правка одной строки → чужие ключи на месте.

## 5. Этапы

### Этап 0. `SettingsModel` и маршрутизация записи

**Файлы:** создать `apps/dj-ui/src/SettingsModel.{h,cpp}`, `apps/dj-ui/src/EngineSettings.{h,cpp}`,
`apps/dj-ui/CMakeLists.txt`, `apps/dj-ui/src/main.cpp` (синглтон `Settings`).

1. Тест `--settings-check --settings-set audio.block_frames=512` — значение пишется в `config.toml`, читается обратно
   **вторым процессом** с тем же файлом.
2. Тест кругового сохранения `EngineSettings`: файл с незнакомым ключом `future_key = 1` и комментарием —
   после записи оба на месте.
3. Реализация: `EngineSettings::set(key, value)`, `SettingsModel` с таблицей «ключ → владелец».
4. Коммит: `feat(settings): модель настроек и запись в три файла через владельцев`.

### Этап 1. Окно и его каркас

**Файлы:** `apps/dj-ui/qml/settings/SettingsWindow.qml`, `qml/shell/ShellLayout.qml` (кнопка-шестерёнка),
`apps/dj-ui/src/checks/SettingsChecks.cpp`, `Checks.h`, `main.cpp` (опция `--settings-window-check`),
`scripts/ui.sh`.

1. Кнопка в шапке открывает окно; окно модальное, слева разделы, справа содержимое, снизу `Close`.
2. `--settings-window-check` требует: окно открывается по кнопке, в нём восемь разделов, `Esc` закрывает,
   окно не выходит за границы окна приложения.
3. Коммит: `feat(ui): окно настроек — каркас и восемь разделов`.

### Этап 2. Интерфейс (всё применяется сразу)

**Файлы:** `SettingsWindow.qml` (раздел «Интерфейс»), `UiSettings.{h,cpp}` (контраст волны переезжает из флага).

1. Каждый контрол пишет через владельца; окно показывает значение из владельца, а не своё копирование.
2. Тест вторым процессом: выставить пресет, доли, шрифт, `waveformBeats`, `frameHz`, `snap/quantize/scrub` —
   второй запуск с тем же `layout.json` показывает то же.
3. Коммит: `feat(settings): раздел «Интерфейс» — всё применяется сразу`.

### Этап 3. Микшер и эффекты (умолчания)

1. Закон кроссфейдера и cut-in, законы ручек/фейдеров, питч, число полос, вид эффекта по декам — через
   `Session`/`UiSettings`; окно показывает то же, что панель.
2. Тест `--settings-check`: сменить в окне вид эффекта деки A, закрыть, второй процесс — `Session.deckFx["A"]`
   совпадает, и движок на первом снимке получает тот же вид.
3. «Громкость мастера по умолчанию» — только если решим добавить поле; без решения контрол не появляется.
4. Коммит: `feat(settings): раздел «Микшер» и умолчания эффектов`.

### Этап 4. Библиотека и анализ

1. Корни коллекции: добавить/убрать путь (через существующие сеттеры), «Пересканировать» — команда `Rescan`.
2. Пороги журнала, «недавно игранное», кэш PCM, доля автогейна — `config.toml` под баннером «после
   перезапуска».
3. Окно модели: лицензия, размер, sha256, кнопка «Скачать» (при отсутствии файла — объяснение, что модель не
   входит в пакет Windows).
4. Коммит: `feat(settings): раздел «Библиотека» и окно модели`.

### Этап 5. Звук (после перезапуска)

1. Все поля `audio.*` и `headphones.*` — через `EngineSettings`, под баннером «применится после перезапуска».
2. Кнопка «Проверить» у устройства: строка уходит в движок одноразовым запуском (`--device-check name`),
   ответ — «существует, 4 канала, 48 кГц» или ошибка.
3. Коммит: `feat(settings): раздел «Звук» — запись в config.toml и проверка устройства`.

### Этап 6. Диагностика и «О приложении»

1. Уровень журнала (в `config.toml` как `diagnostics.log_level`, движок читает вместо переменной при её
   отсутствии), «Открыть папку журналов» (`QDesktopServices`), пороги, `realtime.require`.
2. «Скопировать отчёт»: версия, протокол, устройство, блок, частота — в буфер обмена.
3. Версия, протокол, лицензии в окне.
4. Коммит: `feat(settings): раздел «Диагностика» и «О приложении»`.

### Этап 7. Темы наборами

1. Три набора: «Тёмная» (текущая), «Графит», «Тёплая» — по 16 цветов каждый, применяются целиком.
2. Тест: смена набора меняет `themeBackground` и `themeAccent` вместе, второй запуск показывает выбранный.
3. Коммит: `feat(settings): темы наборами`.

### Этап 8. Проверки, требования, документы

1. `--settings-check` (все три файла) в широком наборе `ui.sh`; `scripts/settings-check.sh` — двухпрогонная
   проверка для значений, которые читает движок.
2. `docs/requirements/traceability.csv`: строки `DJP-UI-003/005/006/007` (сейчас `unverified`) — `passing` в той
   части, что действительно сделана.
3. `docs/qa/evidence/settings/summary.md`; `bash scripts/check-docs.sh`.
4. Коммит: `docs(settings): проверки и требования окна настроек`.

## 6. Карта проверок

| Что | Чем держится |
|---|---|
| Запись не теряет чужих ключей `config.toml` | `EngineSettings` круговой тест: `future_key` и комментарий на месте |
| Значение применяется и переживает запуск | `--settings-check` (второй процесс, те же файлы) |
| Окно существует и закрывается | `--settings-window-check` |
| Движок получает то, что выбрали в окне | `--settings-check --effects`: `Session.deckFx["A"]` = вид на первом снимке |
| Ничего не вышло за границы окна | `--settings-window-check` (геометрия) |
| Требования | `check-docs.sh` + evidence |

## 7. Что сознательно вне этого захода

- Перечисление аудиоустройств списком и смена устройства без перезапуска — нужен код в `dj-audio-io` и
  рестарт-протокол в запускаторе.
- MIDI и горячие клавиши.
- Сведение трёх файлов к одному `settings.toml` (решение 1: пока три).
- Редактор отдельных цветов темы (решение 3: наборы).
- OSС/Ableton Link.
