# models

Здесь лежит **только описание** внешней модели удара — `model.toml`. Весов в репозитории нет: они
скачиваются по запросу пользователя, проверяются по SHA-256 и живут в
`$XDG_DATA_HOME/hauler-dj/models/<id>/<версия>/` (ADR-0012).

## Что где

- `model.toml` — id, вариант, версия, URL артефакта, размер, SHA-256, лицензия, атрибуция, измеренное
  качество и цена. Две записи: `full` (81 МБ, F1 0,956, 5,9 с на трек) и `small` (10,6 МБ, F1 0,948,
  3,5 с).
- Артефакты — в релизе GitHub с тегом `models-v1`, по имени `beat_this-<вариант>.onnx`.

## Как собрать артефакты заново

Экспорт делается из чекпоинта CPJKU (ссылка — в `source`), вне репозитория:

```python
torch.onnx.export(wrapped, (torch.zeros(1, 1500, 128),), out,
                  input_names=["spectrogram"], output_names=["beat", "downbeat"],
                  dynamic_axes={"spectrogram": {0: "batch", 1: "frames"},
                                "beat": {0: "batch", 1: "frames"},
                                "downbeat": {0: "batch", 1: "frames"}},
                  opset_version=17, dynamo=False)
```

Сверка с PyTorch на шести треках корпуса, обе длины куска (1500 и 1200 кадров): худшее расхождение
логитов **8,7·10⁻⁵** для `full` и **7,9·10⁻⁵** для `small` (замер 15.11.2026).

## Как опубликовать релиз

```bash
gh release create models-v1 \
  beat_this-final0.onnx beat_this-small0.onnx \
  --title "Модели удара (Beat This!, MIT)" \
  --notes "Веса Beat This! в ONNX. Код и веса — MIT, CPJKU. Скачиваются приложением по запросу."
```

После публикации сверить `sha256sum` файлов с `model.toml`: при расхождении приложение откажется
устанавливать модель, и это правильно.
