# Матрица устройств

Что мы **знаем** о железе и чем это знание получено (ADR-0005). Пустая клетка — `unknown`, а не
«наверное, работает». Строка добавляется, когда устройство реально подключали; догадки сюда не
попадают.

Колонка «маршрут» — это проверенное прослушиванием соответствие пар каналов шинам, а не вывод из
имён портов (имена врут: дескриптор `FL FR FC LFE` против профиля PipeWire `FL FR RL RR`).

## Как строка заполняется

1. Возможности — `dj-audio-probe` (проба открытия, дескрипторы, перечисление бэкенда);
   приоритет источников: проба > дескриптор > бэкенд.
2. Маршрут — тон по парам (`--tone-pair`) и ответ человека «куда вышел звук». Только так ставится
   `verified`; всё остальное — `inferred`.
3. Органы и экраны — read-only запись репортов (A09), факты в `s4mk3/protocol-notes.md`.
4. Ограничения — то, что устройство физически не может, с ссылкой на требование, которое из-за
   этого не выполняется на данной конфигурации.
