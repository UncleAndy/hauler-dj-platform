# Эталонный стенд

Замеры без зафиксированной конфигурации не принимаются (план §7.4). Ниже — что известно
фактически, и что обязан измерить владелец на физическом рабочем месте.

## Собрано в песочнице агента (2026-11-04)

| Параметр | Значение |
|---|---|
| ОС | NixOS 26.05.20261007.2efa67f (Yarara) |
| Ядро | 6.18.55 |
| CPU | 13th Gen Intel Core i7-13700K; 16 логических CPU видны в песочнице |
| RAM | 62 GiB |
| `/nix` | 937 G, занято 85 % (138 G свободно) |
| PipeWire (библиотека) | 1.6.6 |
| ALSA (alsa-utils) | 1.2.14 |
| Nix | 2.34.8, `sandbox = true`, `max-jobs = 2`, `cores = 3` |

**Чего в песочнице нет и почему это важно:** `/dev/snd` не проброшен, PipeWire-сессия не запущена
(`pw-cli` → «Узел выключен»), нет дисплея (`XDG_SESSION_TYPE=tty`), `scaling_governor` не читается.
Поэтому строки про устройство, частоту, буфер, задержки, `xruns` и RT-приоритеты здесь **не
заполнены** — их измеряет владелец на рабочем столе.

## Обязательно измерить перед A05/G0

- [ ] governor и режим энергопитания при прогоне (`cpupower frequency-info`).
- [ ] аудиоинтерфейс: модель, прошивка, поддерживаемые частоты и число каналов (`pw-cli info`, `aplay -l`).
- [ ] размер callback и quantum при 44,1 и 48 кГц.
- [ ] `callback_time_avg / p99 / max`, `app_xruns`, `system_xruns`, `underruns`.
- [ ] round-trip latency через loopback (DJP-NFR-006).
- [ ] S4 MK3: VID/PID, прошивка, доступные входы/выходы — только после read-only проверки A09.

Шаблон отчёта: `docs/qa/evidence/<task-id>/benchmark.json` + `summary.md`.
