# Страница коллекции: провод и три откаченных переключения

## Что работает (с тестами)

| шаг | коммит |
| --- | --- |
| `Index::page`: `WHERE`/`ORDER BY`/`LIMIT OFFSET`/`COUNT(*)` в SQL, жанры объединением, поиск | `8b66098` |
| типы провода `CollectionQuery`, `CollectionRow`, `CollectionPage` | `d464f68` |
| команда `QueryCollection` и поле `collection` в снапшоте (golden-протокол цел) | `0b61cee` |
| движок отвечает страницей; `page_query`/`collection_row`; 3 теста | `dc4f259` |
| `BridgeClient::queryCollection` / `collectionPage` | `de0b1c2` |
| схема v3: `sample_rate` в строке, миграция через `ALTER`, 38 модульных тестов | `00f2b1e` |
| `attachBridge`; `genresChanged` и `genresPicked` разделены | `10f9855` |

Замеры страницы (SQL, синтетическая база): 5 000 записей — 1,1 с на пересборку индекса целиком
(`--rebuild-index`), 20 000 — 1,7 с. Отдельного замера `Index::page` на 100 000 строк не делалось:
владелец сказал «замер не нужен», и приёмка на 100 000 осталась пунктом 9 плана.

## Три попытки переключить список — все откачены

1. **Синхронное ожидание.** `openCollection` отправлял запрос и прокручивал события, пока не придёт
   ответ. Итог: `RangeError: Maximum call stack size exceeded` в `BrowserPanel.qml` и SIGSEGV в
   `--analyze-check` (гейт красный дважды). Механизм: любой обработчик QML, отвечавший на `changed`
   повторным открытием коллекции, попадал внутрь цикла и прокручивал события снова.
2. **Асинхронно, но с пустым списком.** `openCollection` отправлял запрос и возвращался, не заполняя
   `m_entries`. Итог: `--analyze-check` не дождался списка и гейт покраснел без единой строки об ошибке —
   проверка читала пустоту, которую никто не собирался заполнять.
3. **Прогрессивно** (обход сразу, страница заменяет строки по снапшоту). Итог: `--sort-check` упал на
   загрузке строки в деку — `action 'loading … into A'`, дека не подтвердила. Замена модели сдвинула
   момент, в который проверка кликает и грузит.

**Вывод:** дело не в форме ожидания. Пока проверки не умеют отличить «список пришёл из базы» от
«список обойдён», любая правка источника строк ломает их непредсказуемо. Признак для различения уже
заложен: строки страницы несут `fingerprint`, обойдённые — нет.

## Что нужно следующим шагом

`--collection-page-check`: импортировать три файла (движок пишет индекс), открыть коллекцию, дождаться
строк **с** `fingerprint` и сверить порядок; затем корень, которого в индексе нет, — строки **без**
`fingerprint`. Она даёт свидетеля, и только после неё список переключается.
