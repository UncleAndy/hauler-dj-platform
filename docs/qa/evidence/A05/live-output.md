# A05 — живой вывод через системное устройство

Цель: убедиться, что приложение действительно звучит, а не только считает сэмплы. Проверка идёт
через **устройство по умолчанию** в системе владельца — этого достаточно, чтобы подтвердить
работоспособность софта; замер против референсного стенда (DJP-NFR-003) остаётся за A11.

## Инструмент

`apps/dj-live-probe` — самый короткий настоящий путь сигнала: дека → канальный стрип → master →
устройство вывода. Не WAV-файл: колбэк звуковой карты.

```
dj-live-probe                        # 10 с тона 440 Гц на 0.25 громкости
dj-live-probe --file track.mp3       # то же, но играет файл (MP3 идёт через PCM-кэш, ADR-0008)
```

Ширина канала определяется по устройству: 2 канала — только master, 4 и больше — master на 0/1,
cue на 2/3 (ADR-0005). Ничего не подставляется молча: если устройство не открылось, код выхода 3 и
причина в stderr.

## Прогоны владельца, 2026-11-05

Оба прогона — системное устройство по умолчанию, 48 000 Гц, stereo, запрошенный блок 256 кадров.

| Показатель | Тон 440 Гц | MP3 «Плов и Кодецы» |
|---|---|---|
| `block_honoured` | ✅ true | ✅ true |
| `frames_per_callback` | 256.0 | 256.0 |
| `callbacks` | 1 874 | 2 811 |
| `frames` | 479 744 | 719 616 |
| `audio_seconds` | 9,9947 | 14,992 |
| `interval_min_ms` | 5,190 | 5,272 |
| `interval_p50_ms` | 5,333 | 5,333 |
| `interval_p99_ms` | 5,350 | 5,352 |
| `interval_max_ms` | 12,836 | 9,368 |
| `errors` (в отчёте того прогона — `gaps`) | 0 | 0 |
| `peaks` | 0,25 / 0,25 | 0,1743 / 0,1739 |

Период при 256 кадрах и 48 кГц — **5,3333 мс**, и `p50` совпадает с ним до третьего знака: колбэк
идёт ровно по часам устройства. Тон дошёл с пиком ровно 0,25 — то есть равным заданному гейну:
лимитер не тронул сигнал, путь прозрачен. У MP3 пики 0,1743/0,1739 — это содержимое трека, каналы
почти равны, как и должно быть у сведённой записи.

## Важная оговорка: `gaps: 0` в этих прогонах ничего не доказывал

`max` 12,836 мс — это 2,41 периода, то есть какой-то интервал был заметно длиннее периода. Но
счётчик `gaps` в тот момент считал **ошибки бэкенда**, а не опоздавшие колбэки, и первым интервалом
был промежуток от создания потока до первого колбэка — то есть старт-ап, а не работа. Поэтому
`max` смешивал запуск с работой, а `gaps: 0` не означал «ни один колбэк не опоздал».

Дефект исправлен сразу после этих прогонов (`crates/dj-audio-io`):

- первый интервал не учитывается — он измеряет запуск потока, а не каденцию;
- интервалы классифицируются относительно реального периода: `> 1,5` периода — `late_callbacks`,
  `< 0,5` — `early_callbacks`, ошибки бэкенда — отдельное поле `errors`;
- классификатор вынесен в `classify_interval` и покрыт тестом (в том числе граница ровно 1,5
  периода, которая считается опозданием).

Отчёты ниже (в разделе «после исправления») надо читать по `late_callbacks`, а не по `errors`.

## Что это подтверждает и чего не подтверждает

Подтверждает: приложение звучит, блок соблюдён точно, каденция колбэка идёт по часам устройства,
master-путь прозрачен, MP3-файл играет через тот же путь.

Не подтверждает: DJP-NFR-003 (p99 времени **обработки блока** под 4-дековой нагрузкой < 60 %
периода) — здесь измерялся интервал прихода колбэка, а не стоимость графа; и не подтверждает
работу на референсном стенде (A11), многоканальный вывод, смену устройства на ходу и 2-часовой
прогон на устойчивость.
