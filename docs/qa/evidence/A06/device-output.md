# Движок играет на настоящем устройстве (A06, путь устройства)

`--device SUBSTR` больше не отвергается: движок открывает устройство через `dj-audio-io` (CPAL с
нативным PipeWire, ADR-0002) и держит его, пока жив; `--null-sink` остаётся для проверок без звука.

## Как устроено

Один граф на оба пути (`EngineGraph`): в начале блока сливаются команды, затем деки рендерятся в
канальные стрипы, микшер собирает master и cue, счётчики уходят в `StateCells`. Разница только в
источнике такта: устройство даёт колбэк, null-sink спит до следующего блока. Дефект поэтому не может
жить в одном из двух путей — это буквально один код.

Число каналов берётся у бэкенда (`output_channels`, максимум 4): на устройстве с четырьмя и более
выходами master идёт на первую пару, cue — на вторую (ADR-0005), на стерео cue недоступен. Имя
устройства проверяется **до** захвата сокета, чтобы клиент не подключился к движку, который уже
собирается упасть.

## Что проверено здесь (без звуковой карты)

| Что | Чем | Результат |
|---|---|---|
| Блок графа звучит | `a_block_through_the_graph_is_audible_acked_and_published` | master не пустой, cue тихий (дека не в наушниках) |
| Команда применяется внутри блока | тот же тест | `Ack` получен до конца рендера блока |
| Состояние публикуется | тот же тест | `playing: true`, часы 256 |
| Блок больше подготовленного обрезается | `a_block_larger_than_prepared_is_truncated_not_allocated_for` | часы 128 при запросе 512, хвост тихий |
| Путь колбэка не аллоцирует | `the_callback_path_does_not_allocate` | 0 аллокаций за 16 блоков внутри `RtScope` |
| Null-путь держит реальное время | `dj-engine --null-sink --seconds 2` | 375 колбэков × 256 = 96 000 кадров = 2,000 с |
| Нет устройства — честный отказ | `dj-engine --device default_output` | код 2, сокет не создан |

Реальный звук в этой песочнице проверить нельзя: здесь нет `/dev/snd`. Последняя строка — не отговорка
инструмента, а отказ до открытия устройства.

## Прогон владельца: 60 с на default_output

`docs/qa/evidence/A06/device-output.json` (в файле перед JSON остались две строки баннера dev shell —
это вывод оболочки, сам отчёт начинается с первой `{`).

| Показатель | Значение | Чтение |
|---|---|---|
| Устройство | `default_output`, 2 канала | стерео, поэтому cue = `null` |
| Маршрут | master 0/1 | верно для двух выходов |
| Блок | 256 запрошен, подтверждён | backend не подменил размер |
| Кадры | 2 878 976 за 59,979 с | **48 000 кадров/с ровно** — часы совпадают с реальным временем |
| Колбэки | 11 246 | 11 246 × 5,333 мс = 59,98 с, расхождений нет |
| Опоздания | late 0, early 0, errors 0 | ни одного сбоя каденции за минуту |
| Стоимость блока | p50 5, p99 8, max 15 мкс | 0,15 % периода; DJP-NFR-003 просит p99 < 60 % — запас 400× |
| Интервалы | p50 5,333; p99 5,35; max 5,621 мс | худший выброс 288 мкс от периода |
| Вытеснения | stalled 0, off_cpu 0 | поток ни разу не снимали с CPU внутри блока |
| Пики | **[0,0]** | **тишина** |

### Что это доказывает, а что нет

Доказывает: устройство открыто, поток идёт в реальном времени, размер блока уважается, за минуту ни
одного опоздания, вытеснения или ошибки, стоимость блока — сотая доля периода.

**Не доказывает:** что сигнал доходит до ЦАП. Пики нулевые, и это моя ошибка в инструкции: деки
стартуют на паузе, а я предложил команду без воспроизведения. Прогон честно измерил тишину и ничего
не сказал о пути сигнала. Заодно это показало, что метрика пиков работает: она не выдумала «норму» там,
где звука не было.

Чтобы закрыть путь сигнала, добавлен `--autoplay`: он запускает деки до старта потока, чтобы
ограниченный прогон нёс сигнал. На null-sink это видно по `deck_peaks`:

```
$ dj-engine --null-sink --seconds 1
{"deck_peaks":[0.0,0.0], ...}                 # пауза — тишина, как и должно быть
$ dj-engine --null-sink --seconds 1 --autoplay
{"deck_peaks":[0.19999109208583832,0.19999109208583832], ...}   # дека играет
```

### Что нужно от владельца — повторить минуту с сигналом

```bash
nix develop --command cargo run --release -p dj-engine -- \
  --device default_output --seconds 60 --autoplay > /tmp/engine-with-signal.json
```

Ожидаемое: `peaks` около 0.2 (гейн тона), остальные числа — как в первом прогоне. Тогда путь
сигнала доказан полностью: от деки до выхода устройства.
