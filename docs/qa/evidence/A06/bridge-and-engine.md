# A06 (часть 1): мост и процесс движка

Проверено на живом `dj-engine --null-sink` в песочнице: устройства нет, звук не нужен — часы идут от
счётчика блоков, все правила протокола проверяются полностью.

## Что проверено и чем

| Что | Как | Результат |
|---|---|---|
| Команда подтверждается на своём сэмпле | клиент по unix-сокету: `Play(A)`, ждём `Ack` | `Applied { at_sample: 997376 }` |
| Состояние отражает подтверждённое | снапшот после ack | `playing: true`, `source_frame` растёт |
| Публикация идёт с частотой экрана | 3 с непрерывного чтения | 61 снапшот ≈ 20 Гц |
| Часы идут в реальном времени | два снапшота с интервалом 3 с | 47 987 сэмплов/с при номинале 48 000 → 1,00× |
| Рендер-поток не аллоцирует | `RtScope` + 64 `publish` | 0 аллокаций |
| Снапшот собран из ячеек целиком | `publish` → `read` | playing, hotcue, петля, позиция, гейн, уровни |
| Половины соединения независимы | тест на `UnixStream::pair` | писатель отвечает, пока читатель заблокирован |

## Три дефекта, найденных по ходу

1. **Гейт публикации сравнивался с «прошлой публикацией»** — условие истинно на каждом блоке после
   первого. Движок выдавал ~750 снапшотов в секунду, очередь клиента не пустела, команды с сокета не
   читались, ack не приходил никогда. Исправлено интервалом 50 мс.
2. **Мьютекс в рендер-потоке.** Публикация брала `Mutex` и слала в `mpsc` из аудиопути. Заменено на
   `StateCells` (атомики) + поток-публикатор; тест на ноль аллокаций держит правило.
3. **Один поток на клиента.** Обслуживание ждало сообщение из канала 5 мс, затем парковалось в
   блокирующем `recv()` на сокете: снапшоты не уходили, пока клиент сам не заговорит. Внешне — клиент
   получает приветствие и тишину. Соединение разделено на читателя и писателя, каждый в своём потоке.

## Оболочка говорит с мостом (вторая половина A06)

`apps/dj-ui` больше не заглушка: `BridgeClient` кадрирует сообщения так же, как `dj-bridge`
(4 байта длины + JSON), отказывает кадру длиннее 1 МиБ до всякой аллокации, проверяет
`state_protocol` в приветствии и не показывает ничего, что не пришло снапшотом.

Проверка без экрана и без звуковой карты (`scripts/ui.sh --engine-check`, входит в гейт):

```
dj-engine: listening on .../engine.sock
dj-ui: connected to .../engine.sock (epoch 1793912024)
dj-ui: sent Play(A) as command 1
dj-ui: self-check passed: ack applied at sample 4864, deck A playing per the snapshot (rev 2) after 38 ms
```

Это и есть acceptance A06: настоящий процесс оболочки попросил `Play`, движок подтвердил применение на
сэмпле, и кнопка стала «Pause» не потому, что её нажали, а потому что снапшот сказал `playing: true`.

## Чего ещё нет
- `--device` движок отвергает честно: `dj-audio-io` в процесс не встроен.
- Команды `Load` нет: деки получают источник при старте.
- Оболочка не показывает уровни и позицию в виде полос — только текст; это оформление, не A06.
