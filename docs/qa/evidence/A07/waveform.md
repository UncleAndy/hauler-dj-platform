# Волновые формы: конверт и кэш (A07, часть 1)

`crates/dj-analysis` больше не заглушка: конверт (min/max на столбец), кэш на диске с отпечатком
файла, ссылка на конверт в состоянии деки.

## Время — в кадрах источника

Столбец `n` покрывает кадры `[n * frames_per_bucket, (n + 1) * frames_per_bucket)`. Поэтому
плейхед ставится по `frame / frames_per_bucket` без масштабных поправок — это и есть требование
DJP-MEDIA-003. Тест `the_timebase_maps_a_playhead_to_the_right_column` держит границу: кадр 511 —
столбец 0, кадр 512 — уже первый.

## Кэш и его отпечаток

Отпечаток = размер файла + время изменения в наносекундах. Дёшево читается и меняется при любом
перекодировании, ретегировании или замене файла — то есть ровно тогда, когда старый конверт
описывает другой звук. Формат файла: `DJWAVE01`, отпечаток, частота, размер столбца, число столбцов,
затем пары `min/max` в i16 (точность 1/32767 — для картинки избыточна).

Кэш лежит в `$XDG_CACHE_HOME/hauler-dj/peaks`, никогда в коллекции. Имя файла включает разрешение:
грубый конверт не может быть выдан там, где попросили тонкий.

## Проверено

7 тестов на реальных фикстурах (`tone-1s-44100.flac`, `silence-then-tone-2s-44100.flac`):

| Тест | Что держит |
|---|---|
| `the_envelope_describes_the_file_at_a_fixed_timebase` | 1 с при 44,1 кГц — 86–87 столбцов по 512 кадров, ровный конверт у тона |
| `the_timebase_maps_a_playhead_to_the_right_column` | граница 511/512, за концом — последний столбец |
| `silence_is_flat_and_a_tone_is_not` | тишина < 0,01, тон > 0,3 в нужных местах файла |
| `the_cache_returns_what_it_stored` | второй вызов не декодирует, данные совпадают в пределах шага i16 |
| `a_changed_fingerprint_invalidates_the_cache` | заменённый файл не получает старый конверт |
| `a_different_resolution_never_reuses_another_ones_entry` | 128 и 512 — разные продукты |
| `an_empty_envelope_is_harmless` | пустой конверт не паникует |

Живой прогон через протокол (10 с файла 48 кГц, 960 000 кадров):

```
waveform: {'path': '.../wave-track-c140af7e116af553-512.wave', 'frames_per_bucket': 512,
           'buckets': 1875, 'sample_rate': 48000}
file exists: True size: 7556     # 56 байт заголовка + 1875 * 4
```

1875 = 960 000 / 512 — ровно, без потерь на хвосте.

## Отрисовка

`qml/views/WaveformView.qml` рисует конверт Canvas'ом: по одному столбцу на пиксель, при избытке
столбцов берутся крайние значения группы (иначе трёхминутный трек превратился бы в шум). Плейхед
ставится как `source_frame / frames_per_bucket / columns * width` — из кадра, который присылает
движок, а не из локального таймера.

Чтение файла — `apps/dj-ui/src/Waveform.cpp`: разбор заголовка `DJWAVE01`, проверка длины (объявлено
столбцов против фактических), отказ чужому файлу с сообщением в интерфейсе.

Путь проверяется в гейте целиком — движок анализирует файл, кладёт `.wave`, публикует ссылку, UI
читает:

```
dj-ui: deck A is ready: track
dj-ui: waveform loaded: 282 columns of 512 frames at 48000 Hz
```

282 = 3 с × 48 000 / 512 = 281,25 — округление вверх, хвост не потерян.

## Маркеры и зум

На волновой форме рисуются: петля (полоса и её края), hotcue-метки с номером слота и плейхед. Все
позиции считаются одной формулой — `frame / frames_per_bucket / columns`, то есть из кадров, которые
прислал движок. Той же формулой пользуется Rust (`Peaks::bucket_for`), и она покрыта тестами; QML
проверяется загрузкой сцены (любая ошибка в формулах даёт предупреждение Qt) и глазами владельца.

Зум — колесо мыши (пивот под курсором), двойной клик сбрасывает. Он **пересобирает тот же конверт**:
при отдалении несколько столбцов схлопываются в пиксель с сохранением крайних значений, при
приближении столбец занимает несколько пикселей и показывает свою истинную протяжённость. Детали он
не выдумывает: когда столбцов становится меньше пикселя, панель пишет «envelope limit» — тонкий
конверт должен запросить у движка, это следующий шаг.

Покрытие проверяется в гейте: конверт обязан описать все кадры трека.

```
dj-ui: waveform loaded: 282 columns of 512 frames at 48000 Hz, covering 144384 of 144000 frames
```

144384 = 282 × 512 ≥ 144 000 — последний столбец неполный, но покрытие полное, поэтому метка у самого
конца трека не уедет за край.

## Что осталось в A07
- Зум: грубый и тонкий конверты уже независимы в кэше, но UI просит только обзорный.
- Фоновая подготовка: анализ идёт в потоке загрузчика, то есть блокирует следующую загрузку до
  окончания; отдельная очередь для библиотеки — это A08.
- Маркеры биений (нужен анализ BPM — DJP-MEDIA-006) и stem lanes (R2) — не сделаны.
- Тонкий конверт по зуму не запрашивается у движка: приближение ограничено обзорным разрешением.

## Дефект: одна волновая форма на две деки

Владелец заметил: загрузка в деку A рисовала форму и на деке B. Причина — `Waveform` был
QML-синглтоном, то есть **один читатель на всё приложение**; оба вида писали в него, побеждал
последний, и обе панели рисовали его содержимое.

Исправлено: `WaveformEnvelope` — зарегистрированный тип, каждый вид создаёт свой экземпляр
(`WaveformEnvelope { id: envelope }`). Синглтон в QML нельзя инстанциировать, поэтому смоук-тест
теперь ловит такую ошибку сам: сцена просто не загрузится.

Проверка независимости в гейте — две деки, два файла разной длины:

```
dj-ui: waveform loaded: 282 columns of 512 frames at 48000 Hz, covering 144384 of 144000 frames
dj-ui: sent Load(B) as command 2
dj-ui: two envelopes, kept apart: A 282 columns, B 563 columns
```

282 = 3 с × 48 000 / 512, 563 = 6 с × 48 000 / 512. Совпадение столбцов было бы признаком того, что
читатель снова общий, и проверка падает именно на этом условии.

## Проверка владельцем (2026-11-05)

- Волновые формы больше не перепутываются: загрузка в деку A не рисует форму на деке B.
- Одновременное воспроизведение двух дек на настоящем устройстве — «работает хорошо» на слух.

Второй пункт — это приёмка DJP-MIX-001, которую ни один headless-тест заменить не может: тесты
проверяют маршрутизацию и лимитер по числам, но «звучит правильно» подтверждается только слухом.

## Прокрутка: плейхед в центре, зум вокруг него

По замечанию владельца вид переделан из «показать весь трек» в прокручивающуюся полосу:

- точка воспроизведения всегда в горизонтальном центре; волна движется под ней, а не плейхед по
  волне — так глаз держит одно место, как на CDJ;
- зум (колесо, двойной клик — сброс) меняет только видимую долю трека, поэтому пивот у него один и
  тот же — плейхед; отдельной логики «зум под курсором» больше нет;
- области до первого кадра и после последнего закрашиваются **отдельным цветом**
  (`--waveform-outside-color`, по умолчанию фон полосы `#101317`): у начала трека левая половина
  полосы честно показывает, что там ничего нет, а не тишину внутри трека;
- порядок отрисовки: фон → зоны вне трека → осевая линия → волна (только столбцы в окне) → петля →
  hotcue → плейхед.

Проверки: неверный цвет отвергается с кодом 2 (`dj-ui: not-a-colour is not a colour`), корректный
проходит через QML без предупреждений — оба случая в гейте (`scripts/ui.sh --smoke`).

## Цветная волновая форма и выбор вида

Вид настраивается: `--waveform-style coloured` (по умолчанию) или `plain`. Цветной режим не
раскрашивает пики произвольно — он опирается на данные, которые считает анализ.

`dj-analysis` теперь хранит в каждом столбце, кроме экстремумов, RMS двух отфильтрованных копий
микса: ниже 220 Гц и выше 3,5 кГц (однополюсные фильтры, без FFT — на этом разрешении спектр дороже
картинки). Файл конверта стал `DJWAVE02`, шесть байт на столбец, уровни с квадратичным сжатием.

Проверки:

| Тест | Что держит |
|---|---|
| `the_bands_separate_bass_from_treble` | тон 60 Гц читается как бас (`low` втрое выше `high`), тон 9 кГц — наоборот |
| `the_cache_keeps_the_bands` | уровни переживают запись в файл с точностью до шага u8 |

Чтение в UI проверяется в гейте — конверт обязан прийти с уровнями, иначе цветной режим молча
деградировал бы до одноцветного:

```
dj-ui: waveform loaded: 282 columns of 512 frames at 48000 Hz, covering 144384 of 144000 frames;
        bands low 0.332 high 0.071
```

Оба вида и неверное значение флага (`exit 2`) прогоняются в `scripts/ui.sh --smoke`.
