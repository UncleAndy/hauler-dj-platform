# ADR-0002: основной аудиобэкенд

- **Статус:** **accepted** (2026-11-05) — выбран прямой PipeWire-backend
- **Требования:** DJP-NFR-002…006, DJP-ARCH-007, DJP-ARCH-008, DJP-MIX-003
- **Решение владельца (2026-11-04):** сначала измерения, потом выбор — выполнено

## Решение

Основной аудиобэкенд — **прямой клиент PipeWire** (`dj-audio-io` открывает поток через PipeWire API,
блок = quantum, маршруты задаются линковкой портов). CPAL сохраняется только как адаптер для
окружений без сессии PipeWire (офлайн-рендер, CI, другие ОС по ADR-006) и **не используется** для
живого воспроизведения на рабочем столе.

## Измерения, на которых это основано

### 1. Аппаратные возможности (дескрипторы USB)

| Устройство | Playback | Capture | Частоты |
|---|---|---|---|
| **Traktor Kontrol S4 MK3** | **4 канала** (`FL FR FC LFE`), S32_LE | 8 каналов | 44,1 / 48 / 88,2 / 96 кГц |
| Steinberg UR22C | 2 | 2 | 44,1 … 192 кГц |
| the t.bone SC460 USB | 2 | 2 | 8 … 48 кГц |
| REDRAGON Live Camera | — | 2 | 11,025 … 48 кГц |

### 2. Сессия PipeWire (запуск владельца)

| Узел | Класс | Каналы | Порты |
|---|---|---|---|
| `alsa_output.…S4_MK3_6231754A-00.analog-surround-40` | Audio/Sink | 4 | in: `playback_FL`, `playback_FR`, `playback_RL`, `playback_RR` |
| `alsa_input.…S4_MK3_6231754A-00.analog-surround-71` | Audio/Source | 8 | out: `capture_FL FR RL RR FC LFE SL SR` |

### 3. Функциональные пробы CPAL (48 кГц, тишина, `open-timeout` 1,5 с)

| Устройство | 2 ch | 4 ch | 6 ch | 8 ch |
|---|---|---|---|---|
| `Traktor Kontrol S4 MK3` | ok | ok | ok | ok |
| `pipewire` (ALSA→PipeWire PCM) | **TIMEOUT** | **TIMEOUT** | **TIMEOUT** | **TIMEOUT** |

### 4. Timing trial на `default` (2 с, запрошен блок 256 кадров)

`callbacks 1499`, p99 **1,35 мс**, max **1,38 мс**, провалов > 1,5 периода — 0.
Но фактический интервал 1,33 мс ≈ **64 кадра**: запрошенный блок 256 кадров **не соблюдён**.

## Что доказано, а что нет

**Доказано:**

1. У S4 четыре выхода: master (FL/FR) и cue (RL/RR) — разделимы на уровне портов PipeWire.
2. Путь CPAL через ALSA-PCM `pipewire` в живой сессии **не работает**: открытие блокируется на всех
   числах каналов, то есть ни master, ни cue через него не вывести.
3. Запрошенный размер блока через этот путь не управляется (256 → фактические 64 кадра).
4. Booth отдельным каналом не существует: выходов всего четыре.

**НЕ доказано (и не будет выдано за доказанное):**

1. «ok» на 2/4/6/8 каналах S4 — это **плагинный слой ALSA** (`surround*`/`plug`), который принимает
   любое число каналов и апмикширует. Это не свойство железа: авторитет — дескриптор (4 выхода) и
   порты PipeWire. Число из этой строки в решениях не используется.
2. Нет измерения блока 256 кадров: 1,33 мс — это 64 кадра, поэтому DJP-NFR-002/003/004 остаются
   `unverified`. Их надо мерить на PipeWire-бэкенде, задавая quantum явно.
3. Нет 2-часового soak, нет измеренной round-trip latency, нет hotplug-теста.

## Последствия

1. `dj-audio-io` — клиент PipeWire: `process`-callback, явный quantum (256 кадров = 5,33 мс),
   маршруты master/cue — линковка `playback_FL/FR` и `playback_RL/RR`.
2. RT-контракт ложится на PipeWire естественно: колбэк на фиксированный блок, без аллокаций и без
   ожиданий; всё, что вне колбэка, — отдельные потоки.
3. CPAL остаётся в дереве зависимостей только для офлайна/переносимости; в живом пути его нет.
   Это же снимает риск «приложение дерётся с сервером за карту».
4. Booth: три независимые шины на S4 недостижимы. В UI профиль S4 получает две шины (master, cue),
   booth при необходимости — копия master; в матрице паритета это ограничение устройства, а не
   недоделка.
5. Проверка «сервер занят / устройство пропало» становится обязательным сценарием восстановления:
   сессия может отобрать узел в любой момент (A05/A10).

## Что осталось измерить (уже на PipeWire, в продолжении A05)

| # | Измерение | Критерий |
|---|---|---|
| 1 | quantum 256 кадров, 2 деки, 2 ч | `app_xruns = 0`, p99 < 60 % периода (DJP-NFR-002…004) |
| 2 | 128 кадров | `works` / `not on this host` |
| 3 | round-trip latency через loopback | фактическое число (DJP-NFR-006) |
| 4 | hotplug и отбор узла сервером | звук восстанавливается, состояние не теряется |

## Инструмент

`apps/dj-audio-probe` (A05): дескрипторы USB, перечисление CPAL, функциональные пробы каналов с
таймаутом на открытие, timing trial с указанием **фактического** блока, сводка `pw-dump` с портами.
Read-only: тишина в пробах, входные потоки не открываются, контроллеру ничего не отправляется.
