# ADR-0003: мост QML ↔ Rust

- **Статус:** proposed
- **Требования:** DJP-ARCH-001, DJP-ARCH-004, DJP-UI-001
- **Блокирует:** стабилизацию A06

## Вопрос

Один процесс (in-process C ABI / cxx-bridge, Qt-объект публикует снимки) или отдельный UI-процесс
с IPC (команды и снапшоты по версионированному протоколу)?

## Критерии

1. UI не может задерживать аудиопоток даже при зависании рендеринга (DJP-NFR-007, -016).
2. Снимок 30–60 Гц и `revision`/`epoch` доставляются без блокировок аудио (DJP-ARCH-004).
3. Перезапуск UI не ломает движок (A06 acceptance).
4. Стоимость: сериализация против скорости разработки; тестируемость без GUI.

## Текущее состояние каркаса

`apps/dj-ui` собирается и запускается без движка; `dj-bridge` — пустой крейт. Мост не выбран,
поэтому в коде нет ни C ABI, ни IPC: выбор делается здесь, а не по факту уже написанного кода.

## Решение

Не принято. Для R0 допускается один процесс с разделением потоков (ТЗ §15), но и это требует
зафиксированной записи до стабилизации A06.
