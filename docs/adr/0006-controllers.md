# ADR-0006: контроллеры — транспорт, драйвер, профиль, состояние экрана

- **Статус:** accepted (2026-11-05, решение владельца)
- **Требования:** DJP-CTRL-001…008, DJP-ARCH-007, DJP-NFR-012, DJP-UI-001, DJP-LIC-003, DJP-LIC-006
- **Разблокирует:** A09 (каркас драйвера + read-only), CTRL-005 (экраны), CTRL-006 (моторы —
  только после отдельного ADR о безопасности)

## Контекст

Устройство — это не только аудиоинтерфейс. У контроллера свой набор физических органов, LED и
экраны, а протокол общения с ними бинарный: репорты, смещения, кодировки, чанки. Описательным
конфигом это не закрывается — конфиг покрывает *привязку*, но не *протокол* и не *рендер*.

Одновременно устройства заранее неизвестны, а публичные реализации (Mixxx) распространяются под
GPL-2.0-or-later, что для проекта под MIT OR Apache-2.0 означает: код и маппинги использовать
нельзя (DJP-LIC-003/006), факты о протоколе — можно.

## Решение

### Слои

| Слой | Природа | Кто пишет |
|---|---|---|
| Транспорт (hidraw / IOHIDManager / Windows HID; ALSA-seq / CoreMIDI / WinMM) | код, по одной реализации на ОС | мы |
| Драйвер устройства (кадрирование репортов, LED, протокол экрана, джог) | **код**, крейт на семейство | мы |
| Таблица органов и привязки (орган → действие, слои) | данные, правит пользователь | драйвер поставляет таблицу, пользователь — привязки |
| Состояние и события для экранов | данные от движка/библиотеки | приложение публикует, драйвер потребляет |
| Рендер состояния в пакеты экрана | код драйвера | мы |

### Решения

1. **Драйверы — статические Rust-крейты в дереве**, за Cargo-фичами (`controller-s4mk3`,
   `controller-midi`). Внешний ABI (`cdylib`) и sidecar-процессы — только когда появится
   производитель вне проекта, отдельным ADR. Для R0/R1 пересборка ради нового устройства приемлема,
   а отсутствие FFI убирает целый класс отказов (паника через границу, ручное владение памятью).
2. **Контроллер — ещё один источник команд.** Событие органа нормализуется в
   `ControlEvent { id, value, timestamp }`, контроллер-сервис переводит метку времени в
   `effective_sample` и отправляет `ScheduledCommand` — тот же путь, что у UI и мыши
   (`CommandOrigin::Controller` уже есть в контракте). Отдельной ветки «управление железом» нет.
3. **Слои и режимы** (shift, deck-layer, browser-mode) — конечный автомат в контроллер-сервисе, не в
   драйвере и не в UI. Иначе каждый драйвер реализует shift по-своему.
4. **Экраны: состояние + события, а не только события.**

   | Канал | Содержимое | Свойства |
   |---|---|---|
   | Состояние | трек, артист, remaining, позиция, bpm, key, loop, hotcues, play/cue, уровни | идемпотентно, `revision`/`epoch`, диффы, 10–30 Гц, полный кадр по запросу |
   | События | `TrackLoaded`, `LoopSet`, `HotcueStored(n)`, `BeatTick(phase)`, `PlayStarted`, `OnAir` | edge-triggered, терять допустимо |

   Причина: экран показывает состояние, а потерянное событие оставило бы его неверным до конца сета;
   а непрерывные величины (время, позиция, уровни) событиями вообще не выражаются.
5. **Драйвер объявляет, что умеет показать:** `DisplayCaps { count, kind: Lines(n) | Matrix { w, h,
   format }, max_fps }` плюс маску интересующих полей. Приложение не знает ни разрешения, ни
   кодировки, ни чанкинга — это цель решения. Незнакомое устройство получает generic-профиль
   («две строки: трек и оставшееся время»), устройство без экрана не подписывается вовсе.
6. **Отдельный процесс `apps/dj-controller`.** Не в аудио (USB I/O блокируется, callback не имеет
   права), не в UI (перезапуск UI не должен терять контроллер). Согласуется с ADR-003.
7. **Лестница поддержки — часть архитектуры, а не план на будущее:**
   1) драйвер по идентичности (`VID/PID` + версия прошивки) — полный набор;
   2) нет драйвера → generic MIDI/HID + learn, привязка сохраняется как профиль (DJP-CTRL-002);
   3) нет и этого → устройство работает как аудиоинтерфейс, управление мышью/клавиатурой, приложение
      честно сообщает об этом.
8. **Безопасность (DJP-CTRL-001/004/006):** сначала read-only — карта органов и входящие репорты,
   никаких неизвестных исходящих payload; права через документируемые udev-правила без root;
   моторы — только после отдельного ADR о безопасности, с аварийной остановкой.
9. **Clean-room формально.** Два прохода и два артефакта:
   - проход чтения (отдельная задача) → `docs/hardware/s4mk3/protocol-notes.md`: только факты
     (репорт, смещение, смысл байта, структура кадра) с колонкой происхождения
     `observed` / `public-source` / `assumed`;
   - проход реализации (отдельная сессия/задача) → драйвер пишется **только** по этому документу;
     чтение GPL-источников в этой задаче запрещено и фиксируется в `cleanroom-log.md`.

   GPL-код и маппинги (Mixxx, Encdr) в репозиторий не попадают ни целиком, ни «переводом на Rust».
10. **Тестируемость без железа:** фикстуры-записи сырых репортов, виртуальный контроллер в CI,
    golden-сравнение байтов кадров экрана (как WAV в A01).

### Контракт состояния

`state-v1` **расширяется в A03** полями, которые нужны дисплеям: метаданные трека, remaining,
позиция, bpm, key, hotcues, уровни. Порядок полей = приоритет отображения (по нему generic-профиль
рисует осмысленный минимум). Сделать это позже нельзя: A09 пришлось бы ломать протокол.

## Альтернативы

- **Только события (без состояния).** Отвергнуто: потерянное событие оставляет экран неверным,
  непрерывные величины не выражаются, поздно подключённое устройство нечего рисовать — подробнее в
  п. 4.
- **Отдавать драйверу готовые пиксели (framebuffer).** Отвергнуто: вёрстка и логика отображения
  утекут в каждый драйвер, а приложение всё равно начнёт знать про разрешения.
- **Все устройства через MIDI-learn.** Отвергнуто: дисплеи, LED и джог так не работают.
- **Динамические плагины сразу.** Отвергнуто: потребности нет, риск (ABI, паника через FFI) есть.

## Следствия

1. Крейты: `dj-hid`, `dj-midi` (транспорты), `dj-controller-core` (discovery, трейт драйвера,
   привязки, слои, learn), `dj-controller-s4mk3` (протокол, LED, экраны), `dj-display` (модель
   состояния/событий и трейт рендера); приложение `apps/dj-controller`.
2. A09 сужается до «каркас драйвера + read-only карта органов + фикстуры» — экраны идут отдельной
   задачей (CTRL-005) после PoC протокола, моторы — после ADR о безопасности.
3. `THIRD_PARTY.md`: Mixxx (GPL-2.0-or-later) — reference only, no code, no mapping files.
4. `docs/hardware/s4mk3/{protocol-notes,cleanroom-log}.md` — обязательные артефакты A09.
5. Задержка джога и скретча становится измеримой величиной: транспорт → `effective_sample` → блок;
   обещать «как у Traktor» до замера нельзя.

## Открыто

- Формат файла привязок (JSON) и его версия; где живут пользовательские переопределения.
- Learn: привязка к действиям уровня UI (browser, view) или только к командам движка.
- Нужен ли внешний ABI для сторонних производителей и в какой форме (C ABI или sidecar).
- Разрешения ОС: Input Monitoring на macOS, HID-хендлы Windows.

## Что заставит пересмотреть

Устройство, чей протокол невозможно воспроизвести без копирования GPL-кода. Тогда — честный отказ
от поддержки устройства, а не копирование: лицензионная чистота важнее покрытия железа.
