# RT-контракт аудиопотока

Черновик контракта, на который обязаны опираться A01…A04. Полная версия с instrumentation и
тестами — результат A01; здесь зафиксированы правила, которые нельзя нарушать уже сейчас.

## Границы

1. **Audio callback.** Фиксированный блок, только заранее выделенные буферы. Запрещены:
   heap allocation, mutex/wait, файловый и сетевой I/O, логирование, вызовы Qt, ML, syscall,
   способный блокировать, `unwrap`/`panic` на пути данных.
2. **Состояние меняется только командами.** UI и контроллеры не пишут в DSP-структуры напрямую
   (DJP-ARCH-001). Критические команды (`Play`, `Stop`, `Load`, `Unplug`) не вытесняются потоком
   регуляторов (DJP-ARCH-002, -003).
3. **Снимки состояния** публикуются без блокировки аудио: `revision`, `audio_clock_samples`,
   `epoch`. Устаревший снимок не является подтверждением команды (DJP-ARCH-004).
4. **Инициализация и замена графа** — вне критического потока, на границе блока либо в заранее
   выделенной структуре (DJP-ARCH-005).
5. **Время.** `source_frame` и `audio_clock_samples` — разные шкалы; переход всегда явный, через
   `timebase` и `sample_rate` (DJP-DATA-002).

## Как это проверяется

| Правило | Проверка | Задача |
|---|---|---|
| нет аллокаций/локов в callback | инструментированный callback, счётчики | A01, A11 |
| команда применяется в заданном сэмпле | offline render + сравнение позиции | A01 |
| переполнение очереди не теряет критичные команды | сценарий с flood регуляторов | A01 |
| снимок не блокирует аудио | stress-тест публикации 60 Hz | A01, A11 |

## Статус

Правила зафиксированы; измеримые пороги (p99 < 60 % периода, max < 85 %) — DJP-NFR-003 и
проверяются на эталонном стенде `docs/qa/reference-rig.md`. Пока измерений нет, RT-требования
остаются `unverified`.
