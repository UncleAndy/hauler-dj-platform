# Библиотека: коллекция, теги, идентичность

Срез **MEDIA-005 + MEDIA-004**: теги из файлов, починка кодировок, раскладка в коллекцию,
идентичность композиции по длительности и отпечатку, индекс SQLite. Импорт пачкой с очередью,
паузой и отменой (`MEDIA-007`) и Preview Deck (`MEDIA-008`) — следующий срез.

## Что решено владельцем

| Вопрос | Решение |
|---|---|
| Раскладка | два уровня по одному символу: `collection/<1>/<2>/<Исполнитель> - <Название>.<ext>` |
| Источник имени | **теги**, не имя файла; имя файла приводится к `<Исполнитель> - <Название>.<ext>` |
| Кириллица | как есть, UTF-8, без транслитерации |
| Битые кодировки | распознать и исправить; в коллекции и в базе и имя, и теги корректны |
| Запись тегов | файл в коллекцию пишется уже с исправленными тегами (через `lofty`) |
| Исходник | копируется; исходный файл не трогаем |
| Дубли: политика | по умолчанию спрашивать; в настройках — «заменять если лучше» и «хранить оба» |
| Lossless | по умолчанию лучше lossy |
| Победитель | остаётся в коллекции; при «хранить оба» второй тоже в коллекции, с суффиксом |
| `_duplicates/` | только отклонённые; удаление по сроку (30 дней) или бюджету (5 ГБ) |
| Корень | список каталогов; по умолчанию `$XDG_DATA_HOME/hauler-dj/collection` |
| Выбор корня | тот, где больше свободного места, но с резервом 1 ГБ |
| Файлы вне коллекции | только добавляются внутрь; ссылок наружу нет |
| `.djmeta` | только внутри каталогов коллекции, рядом с файлом; создаётся **после** добавления |

## Порядок добавления

Порядок обязателен: теги обрабатываются до копирования, потому что от них зависит и имя файла, и путь.

1. Файл попадает в `_incoming/` выбранного корня (staging на той же файловой системе, чтобы
   окончательная раскладка была `rename`, а не копированием через диск).
2. **Чтение тегов** (symphonia) — artist, title, album, genre, year, track, обложка не нужна.
3. **Починка кодировок** (см. ниже) — до любых решений об имени.
4. **Параметры качества**: кодек, частота, каналы, разрядность (из параметров кодека), битрейт
   (`размер × 8 / длительность` — средняя по файлу, честная для VBR).
5. **Отпечаток**: декодирование целиком, `dj_fingerprint::of_samples` → `Vec<u32>`, плюс длительность.
6. **Поиск дубля** по индексу (см. «Идентичность»). Возможные исходы: новый / дубль / версия.
7. **Имя и путь**: `<Исполнитель> - <Название>.<ext>` и `collection/<1>/<2>/`. Коллизия имени в
   каталоге — суффикс (см. «Дубли»).
8. **Копирование** в коллекцию под вычисленным именем.
9. **Запись тегов в копию** через `lofty` — только исправленные поля, только если что-то чинили.
10. **`.djmeta`** рядом с файлом в коллекции, затем строка в индексе.
11. `_incoming/` очищается; исходный файл остаётся там, где был.

Отпечаток файла (размер + голова + хвост) остаётся только для инвалидации кэшей. Идентичность
композиции — длительность и chromaprint: они не меняются ни от правки тегов, ни от переименования.

**Что из этого уже сделано (`dj_library::import`):** шаги 2, 3, 7, 8, 9, 10 — чтение тегов, починка
кодировок, имя и путь, копирование, запись тегов в копию, `.djmeta`. Без `_incoming/`, без
параметров качества, без отпечатка композиции и без поиска дубля: коллизия имени сейчас решается
суффиксом ` (2)`, а вопрос «дубль или версия» задаётся очередью (B08, следующий срез). Отпечаток в
`.djmeta` — файловый (размер, голова, хвост), 128 КБ чтения, поэтому импорт стоит около 10 мс на
файл и не декодирует звук.

Имя файла не может кончаться точкой или пробелом: `Super Smash Bros.` даёт `Super Smash Bros.flac`.
Точка в конце законна в названии и незаконна в имени файла — на Windows и в половине инструментов.

## Идентичность: длительность + chromaprint

Длительность разделяет **версии**, отпечаток разделяет **треки**. Порог взят из замера B06:
копии одного трека в разных битрейтах — BER 0,0000…0,0054 (совпадение 0,9946…1,0), обрезка на 2 с —
BER 0,0649, чужие треки — BER 0,49 (совпадение 0,51), время — 21,8 мс на 40-секундное окно.

| Исход | Условие |
|---|---|
| **Дубль** | совпадение ≥ 0,90 и (`|Δдлит| ≤ max(1,5 с, 0,5 %)` **или** сдвиг отпечатка объясняет разницу) |
| **Версия** | совпадение ≥ 0,90, но ни допуск длительности, ни сдвиг не сходятся (radio / extended / remaster) |
| **Новый** | совпадение < 0,85 |

**Сдвиг объясняет разницу.** Копия, у которой отрезали начало, сдвинута в отпечатке ровно на
отрезанное: при обрезке 2 с лаг составил −16 элементов, а один элемент — 0,1238 с, то есть 1980 мс
против 2000 мс разницы. Радио-версия и extended-микс так не совпадают, поэтому правило разделяет
«обрезанная копия» и «другая версия» без порогов на длительность. Проверено на наборе с известным
ответом (`docs/qa/evidence/B08`): три пары «обрезанная копия против полной» дали сдвиг 1980 мс при
разнице 2000 мс и были названы дублем, а не версией.

Кандидаты ищутся не перебором: в индекс кладутся подотпечатки (элементы `Vec<u32>`, каждый —
окно ≈0,12 с) с их смещением; для нового трека берутся его подотпечатки, считаются попадания по
`track_id`, и полная доля совпадения считается только для верхушки списка. Перебор «новый против
всех» на 100 000 треках — около 50 секунд на трек, индекс — миллисекунды.

## Дубль или версия: аудио и теги отвечают на разные вопросы

**Граница приёма:** отпечаток чувствителен к частоте дискретизации. Один и тот же сигнал на 22,05 и
44,1 кГц даёт совпадение 0,83 — ниже порога 0,90, то есть такие копии считаются разными записями. На
коллекции владельца все дубли были одной частоты, поэтому это не проявилось; если понадобится ловить
копии с другой частотой, сравнивать придётся ещё и по длительности с названием.

**Аудио отвечает за «та же запись».** Отпечаток совпадает у копий одного исполнения независимо от
кодека, громкости и обрезки; у radio и extended он расходится или объясняется сдвигом.

**Теги отвечают за «то же издание».** `Bones (Dub Mix)` и `Bones (Extended Mix)` — одно исполнение,
проданное дважды, и согласие 0,91 не делает их копиями; `(Bassboost …)` — другой мастеринг той же
записи. Издание определяется словарём в скобках: `dub`, `extended`, `radio`, `club`, `instrumental`,
`acoustic`, `live`, `remix`, `edit`, `rework`, `remaster`, `bassboost`, `sped`, `slowed`, `vip`,
`bootleg`, `mashup`, `flip`, `cover`, `demo`, `reprise`, `orchestral`. Скобки, которые изданием не
являются, в счёт не идут: `(feat. …)` и `(prod. …)` называют людей, `(Original Mix)` — то же, что
голое название.

Порядок вердикта: согласие ниже 0,90 — разные записи; разные наборы слов издания — версия; иначе
дубль, если разница длительности в допуске или объясняется сдвигом отпечатка.

Допуск по длительности зависит от пары: у lossy против lossless он `max(3 с, 1 %)`, потому что
энкодер добивает длительность до целых кадров и держит свою задержку — FLAC и mp3 одного трека
расходятся на 1,7 с, оставаясь одной записью; у пары одного вида — `max(1,5 с, 0,5 %)`.

## Дубли: качество и судьба варианта

Сравнение качества по порядку, первый различитель решает:

1. lossless (FLAC/WAV/ALAC) лучше lossy (MP3/AAC/OGG);
2. частота дискретизации, затем разрядность;
3. битрейт (для lossy);
4. измеренная полоса: где кончается спектр (mp3 128 обрезан около 16 кГц, 320 — около 20 кГц);
5. клиппинг: доля отсчётов на полной шкале, меньше — лучше;
6. полнота: при почти равной длительности выигрывает более длинный вариант.

**Что уже сделано:** проверка до копирования. `dj_library::import::import_checked` декодирует файл,
считает chromaprint, ищет ту же запись в каталоге коллекции и возвращает `Placed`, `Duplicate` или
`Version`. `Duplicate` не копируется — по умолчанию спрашивают; `Version` кладётся рядом и
сообщается. Каталог (`identity::Catalog`) индексирует подотпечатки: полное сравнение получают только
треки с ≥ 8 общими подотпечатками, не больше трёх кандидатов. Печать живёт в `.djmeta`
(base64 от little-endian `u32`), чтобы переезжать вместе с файлом.

**Политики (`import::Policy`):** `Ask` (по умолчанию) — дубль не копируется, вызывающий спрашивает;
`ReplaceIfBetter` — остаётся лучшая копия (`quality::better`: lossless над lossy, затем частота,
разрядность, средний битрейт), проигравший уходит в `_duplicates/` вместе со своим `.djmeta`;
`KeepBoth` — обе остаются, новая получает суффикс ` (2)` и `variant` в `.djmeta`.

**Чего ещё нет:** вопроса в оболочке (окно импорта) и удаления из `_duplicates/` по сроку или
бюджету места — каталог копится, чистка отдельной задачей. Пара с `variant` пока не исключается из
проверки на следующих добавлениях.

Политика (`ask` по умолчанию, меняется в настройках):

- `ask` — диалог с числами обоих вариантов и тремя кнопками: оставить новый / оставить старый /
  оставить оба;
- `replace_if_better` — замена без вопроса, если новый лучше по порядку выше;
- `keep_both` — оба остаются всегда.

«Оставить оба» и замена победителя не отправляют ничего в `_duplicates/`: победитель живёт в
коллекции, второй — тоже, с суффиксом в имени: маркер, заданный пользователем, иначе номер.

```
collection/A/B/Abba - Dancing Queen.flac
collection/A/B/Abba - Dancing Queen (винил-рип).flac
collection/A/B/Abba - Dancing Queen (2).flac        ← маркер не задан
```

Маркер хранится в `.djmeta` (`variant`) и показывается колонкой в браузере. Пара, помеченная
маркером, больше не считается дублем при следующих добавлениях.

`_duplicates/` — только отклонённые файлы: удаление через 30 дней **или** при превышении 5 ГБ, что
наступит раньше, от старых к новым. Победитель не удаляется никогда.

## Кодировки тегов

Встречаются cp1251, KOI8-R, cp866 и двойное кодирование (UTF-8, прочитанный как cp1251 —
`ÐœÐ¾ÑÐºÐ²Ð°`). Распознавание при добавлении:

1. строка валидна как UTF-8 и не выглядит как мохибейк — оставляем;
2. иначе перебираются кандидаты (cp1251, KOI8-R, cp866, Latin-1) и двойное раскручивание;
3. выбор — по оценке «похоже на текст»: доля букв против служебных и непечатаемых, частоты русских
   букв, отсутствие суррогатов;
4. исходная кодировка сохраняется в индексе для аудита.

Догадка проверяется ещё и алфавитом: слово, в котором смешаны латиница и кириллица, — признак
неверной догадки, а не починки. `Käärijä`, прочитанное как cp1251, даёт `Kддrijд`: правило
отклоняет такого кандидата и оставляет имя как есть. Настоящий мохибейк даёт слова целиком в одном
алфавите, поэтому проверка ничего не ломает.

Исправленные значения пишутся в файл **коллекции** (копию), исходный файл не изменяется.

## Теги: чтение и запись

Чтение — symphonia (уже в дереве). Запись — `lofty` (MIT): ID3v2 для MP3, **Vorbis comments для
FLAC и OGG**, атомы MP4 для M4A.

**Набор фич symphonia — часть контракта, а не мелочь сборки.** `default-features = false` означает,
что каждая фича выбирается нами. Без `id3v2` MP3-ридер не пропускает блок ID3v2: он ищет
синхрослово с начала файла и первым находит `FF FE` — BOM UTF-16 в первом текстовом кадре, — что
читается как заголовок MPEG Layer I. На реальной коллекции это стоило 37 файлов из 114
(«unsupported audio codec») и тегов у всех 114. Включены `id3v2`, `id3v1`, `ape`; после этого
777 из 777 файлов читаются и имеют artist+title. Любое новое расширение контейнеров начинается с
проверки, что фича тегов включена, — иначе симптомом будет не «нет тегов», а «файл не декодируется».

Пишем только те поля, которые чинили или нормализуем: `artist`, `title`, `album`, `genre`, `year`,
`track`. Чужие теги (ReplayGain, комментарии, обложки, ReplayGain-теги плееров) не трогаем никогда.
Свои данные — тональность, BPM, маркер варианта, точки, лупы — остаются в `.djmeta`, не в тегах.

## Раскладка

Префикс собирается из **значимых символов** (буквы и цифры, без разделителей): сначала исполнитель,
затем название, пока не наберётся два. Каталог — верхний регистр; имя файла — как в теге.

| Теги | Путь |
|---|---|
| `Abba` / `Dancing Queen` | `A/B/Abba - Dancing Queen.flac` |
| `A` / `Alone` | `A/A/A - Alone.flac` |
| `12 Stones` / `Broken` | `1/2/12 Stones - Broken.flac` |
| `Ёжик` / `Туман` | `Ё/Ж/Ёжик - Туман.mp3` |
| тегов нет, файл `!!! - Track.mp3` | `T/R/!!! - Track.mp3` |
| в имени нет ни букв, ни цифр | `#/#/…` |

Ёмкость: около 4900 каталогов на кириллицу с латиницей и цифрами; на 100 000 треков — 20–40 файлов
в каталоге.

## Корни коллекции

Корень — список каталогов. Каждый корень — отдельный том в терминах `dj-library` (`volume` + `root`).
Внутри корня: `_incoming/`, `_duplicates/` и двухуровневая раскладка. `.djmeta` — только рядом с
файлом внутри корня.

При добавлении выбирается корень с наибольшим свободным местом на разделе, но не выбирается тот, где
после записи останется меньше 1 ГБ.

## Потоки

Обработка файла — декодирование и отпечаток — независима от других файлов, поэтому импорт идёт
параллельно. Число потоков — настройка: по умолчанию по числу ядер, `1` — законный выбор на
медленном диске, где параллельное чтение только мешает. Замер на 32 файлах по 30 секунд
(`docs/qa/evidence/B08`): один поток — 18,4 с, шестнадцать — 2,4 с, то есть 7,7×; на длинных
треках выигрыш ближе к числу ядер, потому что накладные расходы на файл перестают быть заметными.

Работа распределяется по файлам, а не по каталогам: размеры файлов до открытия неизвестны, и
каталог из длинных треков иначе достался бы одному потоку. Порядок результатов — по путям, чтобы
вывод и журнал не зависели от того, какой поток успел первым.

**Импорт оказался дешевле анализа и упирается в диск, а не в процессор:** 300 файлов коллекции —
8,8 с одним работником и 2,3 с на шестнадцати, то есть 3,8×. Копирование и разбор тегов не
декодируют звук, поэтому потолок здесь — пропускная способность диска; для анализа (декод плюс
отпечаток) тот же замер дал 15,5×. Оба числа — в `docs/qa/evidence/B08`.

**Очередь (`dj_library::queue::Run`)** — это список файлов и индекс, который работники разбирают
атомарно, плюс:

- `progress()` — дешёвый снимок для UI: всего, сделано, отказов, дублей, доля, «идёт», текущий файл;
  собирается из атомиков и одного мьютекса, поэтому его можно звать каждый кадр;
- `cancel()` — «дальше не бери»: файл, который работник уже несёт, доносится целиком, потому что
  половина импорта хуже, чем никакого;
- `join()` — результаты, отсортированные по путям, и время.

Отмена и прогресс — часть контракта, а не удобство: без них импорт сотни тысяч треков нечем
остановить и не на что смотреть.

Смена пути в настройках: если коллекция не пуста, вопрос «перенести коллекцию в новый путь?». Перенос
идёт с прогрессом, файл за файлом, и на каждый трек одной транзакцией переносятся файл, `.djmeta` и
строка индекса; обрыв возобновляется, а не оставляет индекс с путями, которых нет.

## Схема индекса

```sql
CREATE TABLE roots (
    id           INTEGER PRIMARY KEY,
    path         TEXT NOT NULL UNIQUE,
    added_at_ms  INTEGER NOT NULL
);

CREATE TABLE tracks (
    id           INTEGER PRIMARY KEY,
    root_id      INTEGER NOT NULL REFERENCES roots(id),
    rel_path     TEXT NOT NULL,          -- путь внутри корня, UTF-8
    duration_ms  INTEGER NOT NULL,       -- отсечка кандидатов
    artist       TEXT, title TEXT, album TEXT, genre TEXT,
    year         INTEGER, track_no INTEGER,
    codec        TEXT, sample_rate INTEGER, channels INTEGER,
    bits         INTEGER, bitrate INTEGER,
    variant      TEXT,                   -- маркер варианта
    tag_encoding TEXT,                   -- что было в файле до починки
    added_at_ms  INTEGER NOT NULL,
    UNIQUE (root_id, rel_path)
);

CREATE TABLE fingerprints (
    track_id  INTEGER PRIMARY KEY REFERENCES tracks(id),
    data      BLOB NOT NULL              -- Vec<u32> little-endian
);

CREATE TABLE subfingerprints (
    hash      INTEGER NOT NULL,
    track_id  INTEGER NOT NULL REFERENCES tracks(id),
    offset    INTEGER NOT NULL
);
CREATE INDEX subfingerprints_hash ON subfingerprints(hash);
```

Поиск, сортировка и фильтры браузера читают `tracks`; пути — относительные, поэтому перенос корня не
переписывает каждую строку, а меняет один `roots.path`.

## Приёмка среза

1. **Прогон по коллекции владельца без записи**: сколько файлов, какие форматы и кодировки, сколько
   дублей и версий нашлось, сколько времени занял проход. Числа — в evidence.
2. **Кодировки**: файл в cp1251 читается как русский текст, а не как мохибейк; исходная кодировка
   видна в индексе.
3. **Раскладка**: таблица примеров выше воспроизводится тестом; коллизия имён даёт суффикс, а не
   перезапись.
4. **Идентичность**: копии одного трека в 320/128/OGG находятся как дубль; обрезка на 2 с — как
   версия; чужие треки — как разные.
5. **Качество**: из двух вариантов выбирается lossless; при равном формате — по частоте, разрядности,
   битрейту.
6. **Границы**: ни одна строка индекса не указывает за пределы корней; файл, положенный в
   `_incoming/` и не разобранный, не появляется в коллекции.
7. **Теги**: после добавления файл в коллекции открывается теггером с корректными artist/title;
   чужие теги на месте.

## Что не входит в срез

- очередь импорта с паузой и отменой на 100 000 файлов, обложки, smart playlists (`MEDIA-007`);
- Preview Deck и drag-and-drop (`MEDIA-008`);
- перенос коллекции между корнями (делается вместе с `MEDIA-007`: та же машинерия прогресса);
- запись `key`/`bpm` в теги файлов: они живут в `.djmeta`.
