# Выпуск релиза

Порядок, которым собирается выпуск: одна команда делает пакеты, заметки и черновик релиза на GitHub. Здесь — что она
делает, что должно быть готово до неё и что остаётся человеку.

## Что должно быть верно до запуска

1. **Версия в одном месте.** `version` в `Cargo.toml` (секция `[workspace.package]`) — единственный источник:
   `scripts/release.sh` читает её, и `--version X.Y.Z` обязан совпасть, иначе скрипт откажется («Тег с чужим номером увёз
   бы файлы, подписанные неправильной версией»). Отсюда же берётся имя файлов, тег и заголовок релиза.
2. **Заметки написаны руками.** `docs/release-notes-<версия>.md` пишет ассистент по дереву, а не шаблон: `--notes`
   создаёт файл только если его нет, и такой файл — заготовка с «fill in», а не заметки. Разделы: что теперь можно,
   требования, известные ограничения, файлы, чем проверено. Числа берутся из последнего зелёного гейта
   (`grep -oE "^test result: ok\. [0-9]+ passed" лог | awk '{s+=$4} END {print s}'`), а не по памяти.
3. **Гейт зелёный.** `bash scripts/check.sh` → `check.sh: all gates passed`. Дополнительно — прогон в окружении CI:
   `XDG_CONFIG_HOME=$(mktemp -d) XDG_DATA_HOME=$(mktemp -d)/data cargo test --workspace`: проверка, читающая настройки
   машины, локально зелёная, а на машине без `config.toml` красная (так падал `serve_without_an_engine_is_refused`).
4. **Дерево чистое, коммиты отправлены.** Скрипт ничего не пушит и не ставит тегов; черновик релиза привязывается к
   текущей ветке (`gh release create … --target <ветка>`), поэтому тег появится на том, что уже в origin.
5. **`gh` авторизован.** `gh auth status` — иначе `--github` упадёт на отправке (пакеты при этом уже собраны).
6. **Тег свободен.** `git ls-remote --tags origin | grep "v<версия>"` — пусто. Скрипт создаёт `v<версия>` на Publish.
7. **Windows-пакету нужен MSVC-runtime**, если он нужен в поставке: `ORT_CRT_DIR=<каталог>` (см. `docs/windows.md`).

## Одна команда

```bash
nix develop --command dj-release            # всё: --linux --windows --notes --github
nix develop --command dj-release --dry-run  # то же, но черновик не отправляется; печатает команду gh
```

Шаги по отдельности (те же флаги у `scripts/release.sh`):

| флаг | что делает | куда кладёт |
|---|---|---|
| `--linux` | `cargo build --release` движка, запускатора и службы; `ui.sh --build-only`; tar.gz с `.desktop`, иконками и лицензиями; затем deb, rpm и AppImage из одного набора | `dist/release`, `dist/packages` |
| `--windows` | `scripts/windows.sh --all`: zip и MSI mingw-цепочкой, ONNX Runtime, при `ORT_CRT_DIR` — MSVC runtime | `dist/windows` |
| `--notes` | `docs/release-notes-<версия>.md` из шаблона, **только если файла нет** | — |
| `--github` | `gh release create "v<версия>" --draft --title "Hauler DJ <версия>" --notes-file <заметки> --target <ветка>` и загрузка всех файлов и `SHA256SUMS` | черновик на GitHub |
| `--version X.Y.Z` | версия; обязана совпадать с `Cargo.toml` | — |
| `--dry-run` | собирает пакеты и суммы, не отправляя на GitHub | — |

## Что делает человек

1. Проверить черновик на GitHub: заметки, файлы, `SHA256SUMS`.
2. Нажать **Publish** — в этот момент появляется тег `v<версия>` и релиз становится публичным.
3. После публикации — скачать один артефакт и запустить (для Linux — `.deb` на живом дистрибутиве), это единственная
   проверка, которой не может сделать ни гейт, ни этот репозиторий.

## Частые грабли

- **Linux-tar.gz несёт nix-овский интерпретатор ELF**: он запускается на NixOS и не запускается на обычном дистрибутиве,
  поэтому файл называется `-nixos-`. Для остальных — deb/rpm/AppImage, которые несут свои библиотеки.
- **`rpmbuild` на NixOS** ищет макросы в `/usr/lib/rpm` и запускает `brp`-скрипты через `/bin/sh`, которого здесь нет;
  `scripts/linux-packages.sh` подкладывает статический busybox и говорит об этом, если подложить нечем.
- **`wixl` отсутствует** в основной оболочке: он приходит из `msitools` и нужен только для MSI (`scripts/windows.sh
  --msi`).
- **Размеры файлов не пишутся в заметки**: они меняются от сборки к сборке, и таблица «223 МБ» из заметок 0.1.0 —
  исторический факт, а не обещание. Живые размеры и суммы — в файлах релиза.
