# Настройки: критичные значения как параметры

Все числа, которые определяют поведение звука и вердикт по замерам, вынесены в файл настроек
(`crates/dj-config`, формат TOML). Значения по умолчанию — те, которые оправдали замеры; файл нужен,
чтобы следующие тесты могли их изменить без пересборки.

Создать файл с дефолтами:

```
dj-live-probe --write-config ~/.config/hauler-dj/config.toml
```

Прочитать его в прогоне:

```
dj-live-probe --config ~/.config/hauler-dj/config.toml
```

Флаг на команде сильнее файла. Неизвестный ключ — ошибка, а не тихое игнорирование: опечатка в
настройках не должна выглядеть как применённая настройка. Отчёт прогона печатает `thresholds`, по
которым его судили, и `settings_file`, откуда они взялись.

## Аудио

| Ключ | По умолчанию | Диапазон | Почему такой дефолт | Когда менять |
|---|---|---|---|---|
| `audio.sample_rate` | 48000 | 8000–384000 | A05: устройство и проба работали на 48 кГц | 44,1 кГц файлы без ресемплинга; проверка 88,2/96 |
| `audio.block_frames` | 256 | 32–8192, степень двойки | 5,33 мс периода при 48 кГц; блок соблюдался точно | если появятся провалы устройства — 512 (вдвое больше запаса, вдвое больше задержка) |
| `audio.device` | не задано (системное) | подстрока имени | Проверка софта не должна зависеть от конкретного устройства | S4: `--config` с `device = "s4"` |
| `audio.prefetch_seconds` | 2.0 | 0,1–10 | A02: окно 2 с давало `t_ready` 1–2 мс | медленный диск или сетевые файлы — увеличить |

## Диагностика: чем судится прогон

| Ключ | По умолчанию | Диапазон | Смысл |
|---|---|---|---|
| `diagnostics.late_threshold_periods` | 1.5 | 0,1–10 | интервал выше этого — «поздний» |
| `diagnostics.early_threshold_periods` | 0.5 | 0,1–10, меньше late | интервал ниже — «ранний» |
| `diagnostics.stall_threshold_us` | 500 | 1–10000 | блок, в котором поток вне CPU дольше этого, считается вытесненным |
| `diagnostics.expensive_threshold_percent` | 1.0 | 0,01–100 | блок дороже этой доли периода попадает в журнал выбросов |

Первые два порога уже показали себя: при 1,5 периода опоздание в 2,5 мс (интервал 7,85 мс) в `late`
не попадало. Если нужен более строгий вердикт — 1,25 или 1,1, и отчёт покажет, что изменилось.

## Частота вывода (display)

Две частоты, потому что это два разных вопроса.

```toml
[display]
state_hz = 20   # снапшотов в секунду публикует движок
frame_hz = 20   # кадров в секунду рисует оболочка
```

- `state_hz` — сколько раз в секунду движок отправляет полный снапшот (обе деки, счётчики, уровни).
  Двадцать — достаточно для чисел. Флаг: `dj-engine --state-hz N`, допустимо 1..=120.
- `frame_hz` — сколько раз в секунду оболочка перерисовывает полосу и двигает плейхед. Между
  снапшотами позиция проецируется по sample rate трека и текущему темпу, поэтому кадров может быть
  больше, чем снапшотов. Флаг: `dj-ui --fps N`, допустимо 5..=240.

Оба значения по умолчанию 20. Проверено на живом движке (`--null-sink --seconds 2`):

```
 20 Hz requested -> 39 snapshots over 2 s = 19.5 Hz
 60 Hz requested -> 119 snapshots over 2 s = 59.5 Hz
```

Зачем поднимать: на глубоком зуме при быстром скольжении движение становится плавнее. `frame_hz`
делает это дешевле — оболочка проецирует позицию; `state_hz` — точнее, но дороже: каждый снапшот
это IPC и копия состояния.

## Чего в настройках нет намеренно

- **Каналов и маршрутов**: они описывают конкретное устройство и живут в профиле устройства
  (ADR-0005), а не в общих настройках.
- **Порогов качества звука**: их нельзя вывести из микросекунд, нужны прослушивания (A11).
- **Пути к библиотеке**: это данные пользователя (A08), а не параметр звукового пути.

## Настройки оболочки

Эти значения не относятся к движку: их решает UI, и в `crates/dj-config` им не место — тот файл
описывает звук (блок, кэш, пороги) и читается там, где живёт аудиоколбэк.

| Ключ (флаг `dj-ui`) | По умолчанию | Что задаёт |
|---|---|---|
| `--waveform-outside-color ЦВЕТ` | `#101317` (фон полосы) | заливка областей до начала и после конца трека на волновой форме |
| `--waveform-style ВИД` | `coloured` | вид волны: `coloured` — по полосам частот; `plain` — один цвет |
| `--waveform-band-colors НИЗ,СРЕД,ВЕРХ` | `#ff3a1e,#ffd21a,#2f6bff` | цвета трёх полос: бас — ярко-красный, середина — жёлтый, верх — ярко-синий |
| `--waveform-png ЭНВЕЛОПА,OUT.png` | — | нарисовать волну в файл без окна и без звуковой карты |
| `--waveform-span НАЧАЛО,ДОЛЯ` | `0,1` | окно для `--waveform-png`: так проверяется вид на зуме |
| `--waveform-band-gain НИЗ,СРЕД,ВЕРХ` | `1,1,1` | усиление полос перед раскраской: поднять, чтобы полосы было больше видно |
| `--waveform-bar-width PX` | `1` | ширина одного бара; единица — один бар на пиксель |
| `--waveform-bar-gap PX` | `0` | зазор между барами; ноль — сплошная волна, как в деке |

Полосы: бас — до 200 Гц, середина — 200–2500 Гц, верх — выше 2500 Гц. Границы выбраны по обычному
DJ-делению: при верхней границе 4 кГц основной «воздух» тарелок попадал в середину, и холодных
цветов на волне почти не было.

Полоса волны всегда центрирована на точке воспроизведения, поэтому у начала трека слева от
плейхеда — «до трека». По умолчанию эта зона совпадает с фоном полосы и выглядит пустым местом;
если нужен явный край, задайте, например, `#2a2f37`.

Некорректный цвет отвергается с кодом 2 и сообщением — иначе опечатка молча дала бы чёрную зону.

Вид `coloured` опирается на данные, а не на раскраску «на глаз»: анализ считает для каждого столбца
RMS двух отфильтрованных копий микса — ниже 220 Гц и выше 3,5 кГц — и кладёт их в конверт рядом с
экстремумами. Цвет столбца получается из отношения этих двух уровней: при перевесе низа берётся тёплый красный,
при перевесе верха — холодный белый, между ними цвет плавно проходит через янтарный. Поэтому бочка и
хэты видны как разные участки, а не как одинаковые пики. Палитра настраивается флагом
`--waveform-band-colors`.

Значения по умолчанию измерены по скриншотам TRAKTOR PRO 4, которые владелец положил в `tmp/`:
скрипт брал область волны, отбирал насыщенные пиксели и считал медиану по трём полосам. Получилось
тёмно-красный `#a53527`, зелёный `#7aca4c`, сине-фиолетовый `#b156b0`/`#4e73d6`; в настройках они
подняты по яркости (`#c33a26`, `#7aca4c`, `#9b6bd8`), чтобы читались на нашей более тёмной полосе.

Цвет бара считается по спектру: полосы бас 20–280 Гц, середина 280–3500 Гц, верх 3500–20000 Гц
выделяются из БПФ-спектра каждого окна. Каждая полоса делится на корень из своего типичного уровня в
треке (медиана по столбцам): полное выравнивание уводит трек в синий, отсутствие — в красный, а
корень даёт распределение, совпадающее с эталоном. Затем к середине применяется вес 1.5, к верху 2.5, каналы возводятся в степень 1.8, делятся
на максимум из трёх и приводятся к HSV с насыщенностью и яркостью 100%. Поэтому цвета неоновые, без серого и блёклого.

Высота бара — пик блока, нормированный по самому громкому блоку трека: удары дают иглы. Фон
полосы — `#141414`.

Это числа, а не ресурсы: ADR-001 запрещает брать графику NI, но измеренное значение цвета — не
графика, и оно воспроизводимо любым, кто откроет скриншот.

Уровни хранятся в файле с квадратичным сжатием (u8): тихий бас на −30 дБ иначе превратился бы в ноль.
Старые конверты (`DJWAVE01`) не читаются — это кэш, он пересчитывается при первой загрузке.

## Цветовая схема

Гамма измерена по скриншотам TRAKTOR PRO 4 и задана в `UiSettings`: фон `#101010`, панели `#181818`,
приподнятые элементы `#282828`, рамки `#383838`, текст `#c8c8c8` (мягкий серый, не белый), акцент
`#5090f0`. Полоса волны — `#141414`.

Светлая панель — ошибка, а не оформление: диджей работает в темноте. Проверка встроена в
`scripts/ui.sh --smoke` (`--ui-theme-check`): окно снимается offscreen и считается доля ярких
пикселей; больше 25% — провал.

## Стоимость кадра

`--waveform-bench N` рисует полосу N раз (без окна) и печатает стоимость кадра. Без `--load`
используется синтетический конверт на 30 000 столбцов — как у настоящего трека. Гейт
(`scripts/ui.sh --smoke`) запускает его и падает, если p99 больше 8 мс: половина бюджета кадра при
60 Гц.

## Компоновка окна

Раскладка живёт отдельно от настроек движка: аудиопроцессу незачем знать, где стоит панель, и
раскладка не должна уметь сорвать запуск звука. Файл:
`$XDG_CONFIG_HOME/hauler-dj/layout.json` (переопределяется `--layout-file PATH`).

```json
{
    "preset": "traktor",
    "deck_rows": 2,
    "global_percent": 8.0,
    "browser_percent": 28.5,
    "mixer_percent": 14.5
}
```

- `preset` — `traktor` (по умолчанию; числа сняты со скриншотов эталона) или `two-deck`;
- `deck_rows` — 1 или 2: одна пара деков или две (A/C слева, B/D справа);
- `global_percent`, `browser_percent` — доли высоты окна;
- `mixer_percent` — доля ширины, которую занимает микшер между деками;
- `channel_order` — порядок полос микшера слева направо, по умолчанию `CABD`; любая перестановка
  A, B, C, D (повтор отвергается). Флаг: `--channel-order CABD`.

Высота деков не настраивается отдельно: это остаток. Перетаскивание разделителей меняет эти же
числа и сохраняет файл; `--layout traktor` перекрывает файл на один запуск.

Проверка: `dj-ui --layout-check` печатает фактические доли и падает при расхождении больше двух
пунктов. Она входит в `scripts/ui.sh --smoke`.

## Состояние сессии

`$XDG_CONFIG_HOME/hauler-dj/session.json` (переопределяется `--session-file`) хранит то, что окно и
браузер должны помнить между запусками:

```json
{
    "folder": "/home/andy/Music",
    "window": "fullscreen",
    "restore_to": "maximized"
}
```

- `folder` — каталог последней загрузки трека; несуществующий игнорируется, браузер открывается на
  музыкальном каталоге;
- `window` — форма окна: `window`, `maximized` или `fullscreen`. Записывается при каждом изменении
  (включая F11) и восстанавливается при старте;
- `restore_to` — форма, в которую возвращает выход из полноэкранного режима (`window` или `maximized`).
  Хранится отдельно, потому что запуск сразу в полноэкранном режиме всё равно должен знать, откуда
  пришли.

Форма применяется из очереди событий, а не в момент создания сцены: на реальном дисплее режим,
выставленный до появления поверхности, отбрасывается и окно открывается обычным. Пока окно строится,
оно показывается обычным — это не выбор человека, и записывать его в файл нельзя (иначе каждый запуск
забывал развёрнутое окно); запись начинается только после того, как восстановление применено.

Полноэкранный режим — `F11`; выход из него возвращает ту форму, из которой пришли: развёрнутое окно
возвращается развёрнутым, обычное — обычным.

Ветки проверки: `--window-check` (вместе с `--session-file`) — восстанавливает форму из файла, жмёт
F11, требует ожидаемую форму и запись в файле, жмёт снова и требует возврата.
