# Безопасность

## Область

DJ Platform работает локально: нет обязательной телеметрии, аккаунтов и сетевых сервисов
(DJP-NFR-013). Поверхность атаки на этапе M0 — локальные файлы (медиа, метаданные, сессии) и
аппаратные отчёты контроллеров.

## Как сообщать

Приватно владельцу репозитория (`andy@andyhost.world`) или через private security advisory в
GitHub. Не открывать публичный issue с воспроизведением до исправления.

## Что считается уязвимостью

- Паника/крэш или произвольное чтение памяти на битом медиафайле, метаданных, сессии, HID-отчёте.
- Небезопасная десериализация (DJP-NFR-012) и исполнение кода из данных.
- Запись/перезапись пользовательских файлов вне явно выбранных путей.
- Любая телеметрия или сетевой обмен без явного действия пользователя.

## Инварианты, которые нельзя нарушать

1. Аппаратные команды S4 MK3 — только проверенные; неизвестные исходящие пакеты и прошивка не
   отправляются (DJP-CTRL-*, план §1.1 п.7). Моторы — только после отдельного safety gate (ADR-007).
2. Падение ML-worker, пропажа файла или зависание UI не останавливают уже буферизованный звук
   (DJP-NFR-007).
3. Диагностика экспортируется локально, персональные пути по умолчанию редактируются.

## Поддерживаемые версии

Проект на этапе M0, публичных релизов нет: исправления идут только в `main`.
